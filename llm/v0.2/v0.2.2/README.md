# link_llm — 나만의 작은 언어 모델 (v0.2.2)

**초기화 · 정규화.** 깊고 큰 모델을 안정적으로 학습하기 위한 표준 도구 세트 —
**Kaiming 초기화 + weight decay + 조기 종료**(+ 선택적 BatchNorm) — 를 v0.2.1(문맥 N=3)에 얹어 봅니다.
쉽고 작은 프로즈 데이터에선 이 도구들이 아직 큰 효과가 없지만(그 가치는 v0.3 트랜스포머·v0.4 스케일업에서),
도구 자체를 갖춰 두는 게 이 버전의 핵심이에요.

## v0.2.1 → v0.2.2, 무엇이 바뀌었나요?

| | v0.2.1 | v0.2.2 |
|---|---|---|
| 초기화 | 기본(default) | **Kaiming/Xavier** (tanh 이득 반영) |
| 정규화 | weight_decay 0 | **weight_decay 1e-4** |
| 조기 종료 | ✅ 검증 PPL 기준 | ✅ 검증 PPL 기준 (동일) |
| BatchNorm | 없음 | **토글(`USE_BN`)** 로 실험 가능 |
| 검증 PPL | 3.39 | 3.49 |

## v0.2.1과 거의 같은 성적 — 왜?
- v0.2.1은 이미 **조기 종료**가 켜져 과적합 없이 학습해요(프로즈 검증 3.39).
- v0.2.2가 더한 초기화·weight decay·BatchNorm 토글은 **깊고 큰 모델**에서 빛나는 도구라,
  쉽고 작은 프로즈에선 이득이 거의 없어요(검증 3.49 로 오히려 근소하게 높음).
- 즉 **모든 기법이 모든 규모에서 통하진 않는다** — 도구의 진가는 v0.3 트랜스포머·v0.4 스케일업에서 드러나요.

## 정직한 실험 — BatchNorm은 여기선 손해

**BatchNorm을 켜면 오히려 검증 PPL이 올라가요.** BatchNorm은 **깊고 큰 모델**에서 빛나는 기법이라,
작고 쉬운 프로즈 데이터엔 배치 통계가 노이즈로 작용해 손해예요. → 기본값 `USE_BN=False`.
> 💡 **교훈: 모든 기법이 모든 규모에서 통하진 않는다.** `USE_BN=True`로 바꿔 직접 확인해 보세요.

## 구조

```
(앞 N토큰) → 임베딩 concat(N·E) → fc1 → [BatchNorm(선택)] → tanh → fc2 → logits(V)
```
`build_net`·`init_model`·`load`만 바꾸고, 임베딩·문맥(block_size)·데이터·옵티마이저·조기 종료는 v0.2.1 상속.

## 실행 방법

> ⚠️ **PyTorch** 필요. `pip install torch`

```bash
python3 1.train/train.py     # 초기화·정규화 + 조기 종료 학습 → 0.model/model.pt (+ vocab.json)
python3 2.test/test.py       # 학습/검증 PPL + 문장 완성
```

## 성적표 (같은 프로즈 검증 PPL, 낮을수록 좋음)

| 모델 | 검증 PPL |
|---|---|
| v0.1.4/5 (2토큰) | **2.90** ← 최저 |
| v0.2.0 (임베딩, 2토큰) | 2.94 |
| 카운트 v0.0.9 | 2.96 |
| v0.2.1 (N=3, 조기종료) | 3.39 |
| **v0.2.2 (초기화·정규화, N=3)** | 3.49 |

> 📌 N=3(문맥 더 넓음)이 2토큰보다 아직 안 좋은 건 **데이터가 쉽고 작아 부족**하기 때문이에요.
> 문맥을 넓힌 값을 뽑아내려면 데이터가 더 필요해요(스케일업은 v0.4). v0.2.2는 **깊은 모델을
> 안정적으로·과적합 없이 학습하는 도구**를 갖춘 게 핵심입니다.
