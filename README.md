# link_llm

언어 모델(LLM)을 From Scratch 로, 버전별로 관리하고 웹앱에서 테스트하는 프로젝트입니다.

## 폴더 구조

버전들은 **마이너별 그룹 폴더**(`v0.0`, `v0.1` …) 아래에, 그 안에 각 패치 버전이 들어 있어요.

> 🧭 **데이터는 2단계(실제 LLM 파이프라인과 동일).** 언어 능력은 **산문 사전학습**에서, 대화 능력은 **대화 SFT**에서 옵니다.
> - **사전학습(Pretraining)** — `data/pretrain/{train,valid}.txt` (설명문·이야기·시·상식 **산문**). **현재 v0.0~v0.2가 이걸로 학습**해 '다음 토큰 예측'으로 언어를 익혀요.
> - **지시학습(SFT)** — `data/sft/{train,valid}.txt` (`<사용자>…<봇>…` **대화**). **v0.5(SFT)** 에서 '어시스턴트 말투'를 입힐 때 사용해요.
>
> 두 코퍼스는 **같은 어휘/개체**(사과·강아지·도서관 …)를 공유하도록 `data/lexicon.py` 한 곳에서 정의 —
> v0.5에서 "산문만 알던 모델이 대화를 배우는" 전환이 자연스럽습니다.
> 생성기: `data/pretrain/generate.py`(산문)·`data/sft/generate.py`(대화). 둘 다 시드 고정으로 재현 가능.

```

│   ├── lexicon.py          #   공유 어휘·속성 사전 (두 생성기가 함께 사용)
│   ├── dataloader.py       #   PyTorch Dataset/DataLoader (신경망 버전 공용)
│   ├── pretrain/           #   [사전학습] 산문: generate.py + train.txt · valid.txt  ← v0.0~v0.2가 사용

│   │   ├── v0.0.3/         #   - 문장 끝(<END>) 학습    (lm.py 가 <END> 추가)
│   │   ├── v0.0.4/         #   - 백오프(2→1단어 재시도)  (lm.py 가 백오프 추가)
│   │   ├── v0.0.5/         #   - 개수→확률 + 온도        (lm.py 가 온도 추가)

│   │   ├── v0.1.4/         #   - 2토큰 문맥 신경망 (카운트와 같은 문맥으로 공정한 대결)
```

> 상속·로딩은 그룹을 자동으로 찾아가요: 각 `lm.py` 의 `_load_prev` 는 이전 버전 이름
> (예: `v0.0.9`)에서 그룹(`v0.0`)을 계산해 `llm/v0.0/v0.0.9/…` 경로로 불러오고,
> `web_service` 도 `llm/<그룹>/<버전>/0.model/model.json` 을 훑어 버전을 찾습니다.

## 코드 구조 (버전별 0.model/lm.py + 상속 사슬)

버전마다 코드가 거의 똑같이 반복되던 것을, **상속 사슬**로 정리했어요.
각 버전의 `0.model/lm.py` 하나에 **NGramLM(기능) + Model(설정)** 이 함께 들어 있고,
그 버전이 **처음 추가한 함수만** 담아 나머지는 이전 버전에서 물려받아요.

```
v0.0.1/0.model/lm.py  NGramLM (기반: 읽기·학습·저장·생성 전부) + Model
      ▲ 상속
v0.0.2/0.model/lm.py  (새 코드 없음 — ORDERS=[2] 설정만으로 앞 2단어)
      ▲
v0.0.3/0.model/lm.py  + prepare()/is_end()      ← 문장 끝 <END>
      ▲
v0.0.4/0.model/lm.py  + next_token()/can_continue()  ← 백오프
      ▲
v0.0.5/0.model/lm.py  + choose()                ← 확률 + 온도
      ▲
v0.0.6/0.model/lm.py  + tokenize()/detokenize() ← 문장부호 분리
      ▲
v0.0.7/0.model/lm.py  + choose()/generate()     ← top-k / top-p 샘플링
      ▲
v0.0.8/0.model/lm.py  + chat()/build_chat_context()  ← 대화 형식 + 멀티턴
      ▲
v0.0.9/0.model/lm.py  + token_prob()/perplexity()    ← 퍼플렉서티 평가
```

- **각 버전 `0.model/lm.py`** — `NGramLM`(그 버전이 새로 추가/변경한 함수) + `Model`(설정 `ORDERS`).
  → "이 버전이 뭘 더했나"가 한눈에.
- **`1.train/train.py`·`2.test/test.py`** — `0.model/lm.py` 를 불러와 실행하는 **얇은 껍데기**.
  → 신경망(v0.1.0~) 은 학습이 끝나면 에폭별 손실 곡선을 `1.train/loss.svg` 에 남겨요
    (matplotlib 없이 SVG 를 직접 그립니다 — 의존성은 torch 하나 그대로).
    학습 산출물이라 **커밋하지 않아요** — `1.train/train.py` 를 돌리면 생깁니다.
  → 신경망 버전은 **조기 종료(early stopping)** 도 켜져 있어요. 매 에폭 검증 PPL 을 재서
    좋아지지 않으면 멈추고 **가장 좋았던 가중치로 되돌려** 저장하므로, `EPOCHS` 는
    맞춰야 하는 값이 아니라 넉넉한 상한이면 됩니다
    (PyTorch 본체엔 없는 기능이라 `lm.py` 안에 직접 구현 — 의존성은 torch 하나 그대로).
- **`web_service/server.py`** — 선택된 버전의 `0.model/lm.py` 를 불러와 `generate` 만 호출.

> 폴더 이름에 `.` 이 있어 일반 `import` 가 안 되므로, 이전 버전 `lm.py` 는 파일 경로로
> 불러와요(각 `lm.py` 상단의 `_load_prev`). "이 버전이 뭘 바꿨나"는 그 `lm.py` 하나만,
> "전체가 어떻게 도나"는 `v0.0.1/0.model/lm.py` 부터 사슬을 따라 읽으면 됩니다.
> 모델 저장 형식은 개수 세기(v0.0.x) 버전은 `{ "max_order", "tokenizer", "tables" }` 를 담은
> `model.json` 하나예요. 신경망(v0.1.x~) 버전은 **PyTorch 표준**으로 나눠 저장해요 —
> 가중치는 `model.pt`(`torch.save(net.state_dict())`), 어휘는 `vocab.json`(`{tokenizer, vocab}`).
> 불러올 때 저장된 가중치 모양에서 은닉 크기를 복원해 신경망을 다시 만들고 `load_state_dict` 로 채웁니다.

## 클래스 이름은 왜 `NGramLM` 인가요?

`NGramLM` 은 **N-gram + LM** 을 합친, NLP(자연어처리)의 **표준 용어**예요.

- **N-gram** — "연속된 n개의 토큰(단어) 묶음". 우리 모델이 하는 일이 바로
  *"앞의 몇 개 토큰을 보고 다음 토큰을 맞히기"* 라, 토큰 묶음의 등장 횟수를 세는
  **n-gram 언어모델** 이에요.
- **LM** — **Language Model(언어 모델)**. 다음 토큰의 확률을 매기는 모델의 표준 약자.

즉 `NGramLM` = **"N-그램 언어 모델"** (교과서에 그대로 나오는 이름).

**왜 이 이름을 골랐나**

1. **하는 일을 정확히 표현** — 신경망이 아니라 "n-gram을 세는" 방식임을 이름만으로 알 수 있어요.
2. **모든 버전을 아우름** — `ORDERS` 설정만 바꾸면 앞 1단어·2단어·백오프를 다 처리하므로,
   특정 버전에 묶인 `BigramModel` 같은 이름보다 일반적인 `NGram` 이 맞아요.
   (참고: `ORDERS` 는 '문맥 길이'. `order=1` 은 사실 2-gram, `order=2` 는 3-gram — n = 문맥 길이 + 1)
3. **표준 용어라 '진짜'와 연결** — 나중에 논문·교재를 볼 때 바로 이어져, 교육용으로 좋아요.
4. **신경망 시대와 대비** — v0.1.x 에서 신경망을 도입하면 `NeuralLM`·`MiniGPT` 같은 다른 이름을 쓸
   거예요. `NGramLM` 이라는 이름이 **"개수 세기 시대의 모델"** 임을 분명히 표시해 줍니다.

> 참고: README 본문은 언어 모델을 `LLM` 으로 줄여 쓰지만, 코드 클래스명은 관례적인 표준 약자
> `LM`(Language Model)을 따릅니다.

  자세한 설명은 [llm/v0.0/v0.0.7/README.md](llm/v0.0/v0.0.7/README.md) 참고.

  "얼마나 잘 맞히나"를 하나의 숫자(PPL)로 재요. 여기에 **순위로 재는 평가**(top-1/top-5 정확도,

  모든 버전이 상속해요. **개수 세기 시대(v0.0.x)의 완성**이자, 신경망과 비교할 기준선.
  자세한 설명은 [llm/v0.0/v0.0.9/README.md](llm/v0.0/v0.0.9/README.md) 참고.
- [**v0.1.0**](llm/v0.1/v0.1.0/) — **신경망 bigram + PyTorch autograd**: 개수 세기 대신 가중치 `W` 를
  경사하강으로 **학습**해요(미분은 autograd 가 대신). 확률 엔진만 신경망으로 바꾸고 나머지(대화·샘플링·PPL)는
  그대로라 웹앱이 그대로 로드해요. **신경망 시대(v0.1.x)의 시작.** (실행에 `pip install torch` 필요)
  자세한 설명은 [llm/v0.1/v0.1.0/README.md](llm/v0.1/v0.1.0/README.md) 참고.
- [**v0.1.1**](llm/v0.1/v0.1.1/) — **미니배치·벡터화 학습**: 모델(신경망 bigram)은 v0.1.0 그대로이고,
  학습만 **full-batch → 미니배치 SGD**(매 에폭 셔플 + 배치 단위 갱신)로 바꿨어요. 저장 형식이 같아
  웹앱이 그대로 로드하고, PPL 이 v0.1.0 과 비슷하면 "방법만 바꿔도 결과는 같다"가 확인돼요.
  자세한 설명은 [llm/v0.1/v0.1.1/README.md](llm/v0.1/v0.1.1/README.md) 참고.
- [**v0.1.2**](llm/v0.1/v0.1.2/) — **옵티마이저(`torch.optim`)**: 손으로 하던 파라미터 갱신을
  `optimizer.zero_grad() → backward() → optimizer.step()` 표준 3줄로. `OPTIMIZER` 로 **SGD / momentum / Adam**
  을 골라 수렴을 비교해요. 모델·데이터·저장 형식은 그대로. 자세한 설명은 [llm/v0.1/v0.1.2/README.md](llm/v0.1/v0.1.2/README.md) 참고.
- [**v0.1.3**](llm/v0.1/v0.1.3/) — **정규화·초기화**: `weight_decay`(L2)·가중치 초기화(·label smoothing)로
  **과적합을 눌러 일반화**를 개선해요. 목표가 손실↓ 이 아니라 **학습 vs 검증 PPL 격차↓** (v0.0.10 스무딩과 같은 정신).
  모델·저장 형식은 그대로. 자세한 설명은 [llm/v0.1/v0.1.3/README.md](llm/v0.1/v0.1.3/README.md) 참고.
- [**v0.1.4**](llm/v0.1/v0.1.4/) — **2토큰 문맥 신경망**: 지금까지 앞 1토큰만 보던 신경망을 **앞 2토큰**으로 넓혀
  (one-hot 2개 concat → `nn.Linear(2V, V)`), 카운트(v0.0.9, 앞 2토큰)와 **같은 문맥의 공정한 대결**로 만들어요.
  산문 사전학습 기준 **검증 PPL 3.02** — 카운트(2.96)에 근소하게 못 미쳐요(조기 종료를 학습 손실로 바꾼 뒤 살짝 과적합).
  자세한 설명은 [llm/v0.1/v0.1.4/README.md](llm/v0.1/v0.1.4/README.md) 참고.
- [**v0.1.5**](llm/v0.1/v0.1.5/) — **기준선 대결(캡스톤)**: 같은 학습/검증 데이터로 **v0.0.9(카운트) vs 신경망(1토큰·2토큰)**
  의 PPL 을 나란히 재서 "신경망이 정말 이겼나?"를 확인해요. `2.test/test.py` 가 대결표를 출력합니다.
  결과(산문): 1토큰 신경망(4.09)도, 같은 2토큰 v0.1.4~5(**3.02**)도 카운트(2.96)를 **못 이겨요** — 조기 종료를 학습 손실로 바꿔 검증 최적점을 지나친 탓(교훈: 조기 종료는 검증을 봐야 함). **신경망 시대(v0.1.x) 완성.** 자세한 설명은 [llm/v0.1/v0.1.5/README.md](llm/v0.1/v0.1.5/README.md) 참고.
- [**v0.2.0**](llm/v0.2/v0.2.0/) — **임베딩 도입**: 입력을 one-hot → **`nn.Embedding`** 으로 바꿔요.
  `nn.Embedding(V,E)(idx) == one_hot(idx) @ C` 동치이지만 **E ≪ V 로 압축·공유**돼, 비슷한 토큰이
  비슷한 벡터를 갖게 학습 → 문맥끼리 강점 공유. 2토큰 문맥·2층 MLP·저장방식은 v0.1.5 그대로.
  결과(산문): **검증 PPL 3.06** — 카운트(2.96)도 one-hot 2토큰(3.02)도 못 넘어요.
  데이터가 쉬워 '압축·공유'보다 one-hot 의 '구별력'이 아직 크거든요(E·데이터 규모가 커질수록 임베딩이 유리).
  대신 파라미터가 더 적어요(759K vs 942K) — 지금 임베딩이 주는 건 '효율'입니다.
  **임베딩 시대(v0.2.x)의 시작.** 자세한 설명은 [llm/v0.2/v0.2.0/README.md](llm/v0.2/v0.2.0/README.md) 참고.
- [**v0.2.1**](llm/v0.2/v0.2.1/) — **문맥 확장(`block_size`)**: v0.2.0 의 2토큰 고정을 **앞 N토큰**으로 열어요.
  각 토큰 임베딩을 이어붙여(`emb(x).flatten(1)`) MLP 에 넣는 = 진짜 **Bengio(2003) 입력층**.
  `BLOCK_SIZE`(기본 3)만 바꾸면 문맥 길이가 늘어요(2면 v0.2.0 과 동일). `build_net`·`make_pairs`·
  `_context_tensor`·`load` 만 재정의하고 나머지는 상속. 자세한 설명은 [llm/v0.2/v0.2.1/README.md](llm/v0.2/v0.2.1/README.md) 참고.
- [**v0.2.2**](llm/v0.2/v0.2.2/) — **초기화·정규화 도구**: Kaiming 초기화 + weight decay + 조기 종료
  (+ BatchNorm 토글 `USE_BN`)를 갖춰요. 산문 사전학습에선 검증 **3.56** 으로 v0.2.1(3.46)과 비슷하거나
  약간 높아, **쉽고 작은 데이터에선 이 도구들의 이득이 거의 없다**는 걸 그대로 보여줘요
  ("모든 기법이 모든 규모에서 통하진 않는다"). 값어치는 **깊고 큰 모델(v0.3 트랜스포머·v0.4 스케일업)** 에서
  드러납니다. 자세한 설명은 [llm/v0.2/v0.2.2/README.md](llm/v0.2/v0.2.2/README.md) 참고.

## 📏 여러 지표로 비교하기 — `eval_suite.py`

각 버전의 `2.test/test.py` 는 '그 버전 하나'를 봅니다. `eval_suite.py` 는 학습된 버전을
**모두 모아 같은 데이터로** 나란히 재요. 그리고 **지표를 하나만 보지 않습니다.**

```bash
python3 eval_suite.py                 # 학습된 버전 전부
python3 eval_suite.py v0.0.9 v0.2.0   # 고른 버전만
python3 eval_suite.py --quick         # 생성 지표는 느리니 건너뛰기
```

| 지표 | 묻는 것 |
|---|---|
| **PPL** (전체 / OOV 뺀 것) | 확률을 얼마나 잘 배분했나 |
| **top-1 / top-5 정확도** | 1등을 얼마나 맞혔나 |
| **후보 포함률** | 정답을 만들어낼 수 있기라도 한가 |
| **답 고르기 (Recall@1)** | 진짜 답을 가짜 답 9개 사이에서 고르나 |
| **생성 다양성 (distinct-1/2)** | 온도를 바꾸면 답이 실제로 다양해지나 |
| **파라미터 수 · 파일 크기** | 그 성능이 얼마짜리인가 |

실제로 재보면 **지표마다 승자가 다릅니다** — 이게 이 도구의 핵심 교훈이에요.

아래는 **산문 사전학습(`data/pretrain`)** 기준 결과예요.

조기 종료 기준은 **학습 손실(Loss), patience=20**.

```
버전       종류     학습PPL  검증PPL   top-1   top-5   후보有     파라미터
v0.0.9   카운트     2.49    2.96    73.5%   80.8%   97.1%      9,512
v0.1.0   신경망     7.89    8.44    60.7%   74.2%   98.9%    314,696
v0.1.1   신경망     3.60    4.09    64.8%   78.7%   98.9%    314,696
v0.1.4   신경망     2.49    3.02    73.6%   80.9%   98.9%    942,281
v0.2.0   신경망     2.50    3.06    73.5%   80.9%   98.9%    759,753
v0.2.1   신경망     3.05    3.46    73.6%   80.4%   98.9%    209,641

→ 검증 PPL 최저 : 카운트(2.96)  ·  최고 신경망 v0.1.4/1.5=3.02 는 근소하게 못 미침
```

- **쉬운 데이터에선 카운트가 강력한 기준선.** 산문은 in-distribution 예측이 쉬워 카운트(2.96)가 **최저**예요 —
  최고 신경망(v0.1.4/1.5=3.02)도 못 넘습니다. 1토큰(4.09)·넓은 문맥 N=3(3.46)은 더 뒤처져요.
- **왜 신경망이 카운트에 졌나 — 조기 종료 기준.** 조기 종료를 **검증이 아니라 학습 손실**로 보면 모델이
  검증 최적점을 지나 계속 학습해 **살짝 과적합**해요(이전 검증-PPL 기준 땐 2토큰 신경망 2.90 으로 카운트를
  간신히 이겼음). **교훈: 조기 종료는 '검증'을 봐야 일반화 최적점에서 멈춘다.** 진짜 격차는 **v0.5 SFT** 에서.
- **넓은 문맥(N=3)이 손해**(3.46/3.56 > 3.02): 데이터가 쉬우면 넓은 문맥이 과함. 문맥 확장의 값어치는
  더 크고 어려운 데이터(v0.4 스케일업)에서 드러납니다.
- **후보 포함률 97.1% vs 98.9%** — 쉬운 산문이라 카운트도 커버리지가 높아요. 어려운 SFT 데이터에서
  이 격차(표에 없는 조합)가 벌어집니다.
- **크기도 지표입니다.** 카운트는 파라미터 **9.5천 개**로 PPL 2.96 을 내요 — 94만 개짜리 2토큰
  신경망(3.02)보다 **작으면서 더 낮은** 검증 PPL이에요.

> 이제 모든 버전이 루트 `data/pretrain` 을 공용하므로 데이터 지문이 같아 함께 비교돼요.
> (대화 전용 지표 '답고르기'는 산문엔 `<봇>` 이 없어 자동으로 `-` 로 표시됩니다.)
> 신경망 버전을 포함하려면 PyTorch 가 필요하고, 없으면 그 버전만 건너뜁니다.

## 🗺️ 앞으로의 계획 (로드맵)

여기까지가 **개수 세기 시대(v0.0.x)** 예요. 다음은 신경망으로 넘어갑니다.

> **핵심 원칙 — 인터페이스는 고정, '확률 엔진'만 교체.** v0.0.x에서 만든 토크나이저·대화 템플릿(`chat`)·
> 샘플링(온도/top-k·top-p)·생성(`generate`)·퍼플렉서티(PPL)는 그대로 두고, 각 신경망 버전은
> **"다음 토큰 확률을 어디서 얻느냐"(개수 표 → 신경망)만** 바꿔요. **v0.1.0부터 PyTorch autograd 사용.**
>
> 덕분에 **모든 버전이** `0.model / 1.train / 2.test` 구조 + **루트 공용 `data/`** 를 그대로 써서 `web_service` 가 수정 없이 로드하고,
> **학습 → 생성/대화 → PPL 측정**까지 완결되어 **웹앱에서 바로 평가**할 수 있어요.
> (각 마이너의 마지막은 여러 모델을 웹앱에서 나란히 비교하는 **캡스톤** 버전이에요.)

### 최종 목표 — ChatGPT(InstructGPT/GPT-3.5 계열)급 정렬 어시스턴트

## 모르는 단어가 입력되면?

이 모델은 입력 문장의 **마지막 단어**를 시작점으로 문장을 만들어요.

- 마지막 단어가 모델에 **있으면** → 그 단어부터 시작
- 마지막 단어가 모델에 **없으면**(모르는 단어) → 모델이 아는 단어 중 **무작위로 하나**를 골라 시작

즉, 모르는 단어가 들어와도 오류 없이 항상 문장을 만들어 냅니다(폴백 방식).
대신 입력과 상관없는 엉뚱한 답이 나올 수 있는데, 이는 단어의 *의미*를 이해하는 게 아니라
"어떤 단어 뒤에 무슨 단어가 나왔는지"만 세어둔 아주 단순한 모델이기 때문이에요.

## v0.0.2·v0.0.3 에서 단어를 1개만 입력하면?

v0.0.2·v0.0.3 은 **앞 두 단어**로 다음 단어를 찾는 모델이에요. 그래서 입력이 1개뿐이면
두 단어짜리 문맥을 만들 수 없어, 다음 순서로 처리됩니다.

1. 마지막 두 단어가 필요한데 1개뿐 → 문맥을 못 만듦(빈 문맥)
2. 빈 문맥은 표에 없으므로 → **폴백**: 모델이 아는 두 단어 문맥 중 **무작위로 하나**를 골라 시작
3. 그 문맥부터 단어를 이어 붙여 문장을 완성 (v0.0.3 은 `<END>` 에서 자연스럽게 멈춤)

즉, **입력한 한 단어는 결과에 나오지 않고 무시**되며(무작위 시작), 시작 방식은 두 버전이 같고
**끝맺음만** 다릅니다(v0.0.2 는 툭 끊길 수 있고, v0.0.3 은 자연스럽게 마무리).

> ✅ **v0.0.4 부터 해결됨**: v0.0.4 의 **백오프**(앞 2단어가 없으면 1단어로 줄여 재시도) 덕분에,
> `"나는"` 한 단어만 입력해도 `"나는"` 으로 시작하는 문장을 만들 수 있어요. 더 이상 입력이 무시되지 않아요.

### 백오프 전후 비교 (1단어 `"나는"` 입력)

| 버전 | 1단어 "나는" 입력 결과 | 해석 |
|------|----------------------|------|
| v0.0.2 / v0.0.3 (백오프 X) | "단풍이 곱게 물듭니다" / "기분이 조금 나쁩니다" | 2단어 문맥 못 만들어 **입력 무시, 무작위 시작** |
| v0.0.4 / v0.0.5 / v0.0.6 (백오프 O) | "나는 아침에 밥을 먹습니다" 등 | 1단어로 줄여 찾아 **입력을 반영** ✅ |
