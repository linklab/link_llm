# link_llm — 나만의 작은 언어 모델 (v0.1.5)

**기준선 대결 (캡스톤).** 모델이 아니라 **'비교'가 새 개념**이에요.
모델·학습은 v0.1.4(2토큰) 그대로이고, 여러 버전을 같은 데이터로 나란히 재서 대결표를 뽑습니다.

## 실행

> ⚠️ **PyTorch** 필요: `pip install torch`
> 비교할 신경망 버전들은 각자 `1.train/train.py` 로 **먼저 학습**해 두세요.

```bash
python3 1.train/train.py     # v0.1.5 자신을 학습
python3 2.test/test.py       # 대결표 출력
```

## 읽는 법

**① 이긴 건 '신경망'이 아니라 '같은 문맥의 신경망'**
- 앞 1토큰만 보는 v0.1.0~1.3 은 4~6점대로 카운트(2.65)에 **크게 집니다**.
- 문맥을 2토큰으로 맞춘 v0.1.4/1.5 만 **2.62** 로 카운트를 넘어서요.
- 격차 **0.03**, 파라미터 **78배**(69.6만 vs 8.9천) — 이겼지만 압도하진 못했어요.

**② 후보 포함률 97.1% vs 98.9% — 카운트의 근본 한계**
- 카운트는 검증 자리의 약 2.9% 에서 정답을 표에 **아예 갖고 있지 않아요**.
- PPL 에서는 `FLOOR` 가 메워 가려지는 차이가, 이 열에서는 그대로 드러납니다.

**③ 지표마다 승자가 다를 수 있음**
- PPL(확률을 잘 배분) 과 top-1(1등을 잘 맞힘) 은 다른 능력이에요.
- "어느 자로 쟀는지"를 같이 말해야 합니다.

## 공정한 비교인 이유

- 모든 버전이 같은 토크나이저 · `<END>` · `perplexity()` 공식을 사용.
- 확률 엔진(개수 표 ↔ 신경망)**만** 다름.
- v0.1.4~5 는 문맥 길이(2토큰)까지 카운트와 같아 **완전한 사과 대 사과**.
- 학습 안 된 버전이나 torch 없는 버전은 자동으로 **건너뛰고** 이유를 알려줘요.

## 저장 형식 / 웹앱

- 카운트는 `model.json`(개수 표), 신경망은 `model.pt`(state_dict) + `vocab.json`(어휘).
- 각 버전 클래스가 알아서 로드하므로, 웹앱에서 v0.1.5 를 골라 **이어쓰기**로도 평가할 수 있어요.
