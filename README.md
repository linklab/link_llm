# link_llm

언어 모델(LLM)을 From Scratch 로, 버전별로 관리하고 웹앱에서 테스트하는 프로젝트입니다.

## 폴더 구조

버전들은 **마이너별 그룹 폴더**(`v0.0`, `v0.1` …) 아래에, 그 안에 각 패치 버전이 들어 있어요.

> 🧭 **데이터는 2단계(실제 LLM 파이프라인과 동일).** 언어 능력은 **산문 사전학습**에서, 대화 능력은 **대화 SFT**에서 옵니다.
> - **사전학습(Pretraining)** — `data/pretrain/{train,valid}.txt` (설명문·이야기·시·상식 **산문**). **현재 v0.0~v0.2가 이걸로 학습**해 '다음 토큰 예측'으로 언어를 익혀요.
> - **지시학습(SFT)** — `data/sft/{train,valid}.txt` (`<사용자>…<봇>…` **대화**). **v0.5(SFT)** 에서 '어시스턴트 말투'를 입힐 때 사용해요.
>
> 두 코퍼스는 **같은 어휘/개체**(사과·강아지·도서관 …)를 공유하도록 `data/lexicon.py` 한 곳에서 정의 —
> v0.5에서 "산문만 알던 모델이 대화를 배우는" 전환이 자연스럽습니다.
> 생성기: `data/pretrain/generate.py`(산문)·`data/sft/generate.py`(대화). 둘 다 시드 고정으로 재현 가능.

> `web_service` 도 `llm/<그룹>/<버전>/0.model/model.json` 을 훑어 버전을 찾습니다.

## 코드 구조 (버전별 0.model/lm.py + 상속 사슬)

버전마다 코드가 거의 똑같이 반복되던 것을, **상속 사슬**로 정리했어요.
각 버전의 `0.model/lm.py` 하나에 **NGramLM(기능) + Model(설정)** 이 함께 들어 있고,
그 버전이 **처음 추가한 함수만** 담아 나머지는 이전 버전에서 물려받아요.

```
v0.0.1/0.model/lm.py  NGramLM (기반: 읽기·학습·저장·생성 전부) + Model
      ▲ 상속
v0.0.2/0.model/lm.py  (새 코드 없음 — ORDERS=[2] 설정만으로 앞 2단어)
      ▲
v0.0.3/0.model/lm.py  + prepare()/is_end()      ← 문장 끝 <END>
      ▲
v0.0.4/0.model/lm.py  + next_token()/can_continue()  ← 백오프
      ▲
v0.0.5/0.model/lm.py  + choose()                ← 확률 + 온도
      ▲
v0.0.6/0.model/lm.py  + tokenize()/detokenize() ← 문장부호 분리
      ▲
v0.0.7/0.model/lm.py  + choose()/generate()     ← top-k / top-p 샘플링
      ▲
v0.0.8/0.model/lm.py  + chat()/build_chat_context()  ← 대화 형식 + 멀티턴
      ▲
v0.0.9/0.model/lm.py  + token_prob()/perplexity()    ← 퍼플렉서티 평가
```

- **각 버전 `0.model/lm.py`** — `NGramLM`(그 버전이 새로 추가/변경한 함수) + `Model`(설정 `ORDERS`).
  → "이 버전이 뭘 더했나"가 한눈에.
- **`1.train/train.py`·`2.test/test.py`** — `0.model/lm.py` 를 불러와 실행하는 **얇은 껍데기**.
  → 신경망(v0.1.0~) 은 학습이 끝나면 에폭별 손실 곡선을 `1.train/loss.svg` 에 남겨요
    (matplotlib 없이 SVG 를 직접 그립니다 — 의존성은 torch 하나 그대로).
    학습 산출물이라 **커밋하지 않아요** — `1.train/train.py` 를 돌리면 생깁니다.
  → 신경망 버전은 **조기 종료(early stopping)** 도 켜져 있어요. 매 에폭 **학습 손실**과 **검증 PPL** 을
    함께 재서, **둘 중 하나라도** 최저를 갱신하면 계속 학습하고 둘 다 `PATIENCE`(20) 에폭 정체하면
    멈춰요. 그리고 저장하는 건 **검증 PPL 이 가장 낮았던 에폭의 가중치** — 마지막 에폭이 아니라
    **일반화 최적점**입니다. 그래서 `EPOCHS` 는 맞춰야 하는 값이 아니라 넉넉한 상한이면 됩니다
    (PyTorch 본체엔 없는 기능이라 `lm.py` 안에 직접 구현 — 의존성은 torch 하나 그대로).
  → **계산 장치**는 `train.py` 의 `m.DEVICE` 로 고릅니다. 기본 `"auto"` 는 애플 실리콘 GPU(**MPS**)가
    있으면 쓰고 없으면 CPU 예요 (`"cpu"`/`"mps"` 로 못박을 수도 있어요).
- **`web_service/server.py`** — 선택된 버전의 `0.model/lm.py` 를 불러와 `generate` 만 호출.

> 폴더 이름에 `.` 이 있어 일반 `import` 가 안 되므로, 이전 버전 `lm.py` 는 파일 경로로
> 불러와요(각 `lm.py` 상단의 `_load_prev`). "이 버전이 뭘 바꿨나"는 그 `lm.py` 하나만,
> "전체가 어떻게 도나"는 `v0.0.1/0.model/lm.py` 부터 사슬을 따라 읽으면 됩니다.
> 모델 저장 형식은 개수 세기(v0.0.x) 버전은 `{ "max_order", "tokenizer", "tables" }` 를 담은
> `model.json` 하나예요. 신경망(v0.1.x~) 버전은 **PyTorch 표준**으로 나눠 저장해요 —
> 가중치는 `model.pt`(`torch.save(net.state_dict())`), 어휘는 `vocab.json`(`{tokenizer, vocab}`).
> 불러올 때 저장된 가중치 모양에서 은닉 크기를 복원해 신경망을 다시 만들고 `load_state_dict` 로 채웁니다.

## 클래스 이름은 왜 `NGramLM` 인가요?

`NGramLM` 은 **N-gram + LM** 을 합친, NLP(자연어처리)의 **표준 용어**예요.

- **N-gram** — "연속된 n개의 토큰(단어) 묶음". 우리 모델이 하는 일이 바로
  *"앞의 몇 개 토큰을 보고 다음 토큰을 맞히기"* 라, 토큰 묶음의 등장 횟수를 세는
  **n-gram 언어모델** 이에요.
- **LM** — **Language Model(언어 모델)**. 다음 토큰의 확률을 매기는 모델의 표준 약자.

즉 `NGramLM` = **"N-그램 언어 모델"** (교과서에 그대로 나오는 이름).

**왜 이 이름을 골랐나**

1. **하는 일을 정확히 표현** — 신경망이 아니라 "n-gram을 세는" 방식임을 이름만으로 알 수 있어요.
2. **모든 버전을 아우름** — `ORDERS` 설정만 바꾸면 앞 1단어·2단어·백오프를 다 처리하므로,
   특정 버전에 묶인 `BigramModel` 같은 이름보다 일반적인 `NGram` 이 맞아요.
   (참고: `ORDERS` 는 '문맥 길이'. `order=1` 은 사실 2-gram, `order=2` 는 3-gram — n = 문맥 길이 + 1)
3. **표준 용어라 '진짜'와 연결** — 나중에 논문·교재를 볼 때 바로 이어져, 교육용으로 좋아요.
4. **신경망 시대와 대비** — v0.1.x 에서 신경망을 도입하면 `NeuralLM`·`MiniGPT` 같은 다른 이름을 쓸
   거예요. `NGramLM` 이라는 이름이 **"개수 세기 시대의 모델"** 임을 분명히 표시해 줍니다.

> 참고: README 본문은 언어 모델을 `LLM` 으로 줄여 쓰지만, 코드 클래스명은 관례적인 표준 약자
> `LM`(Language Model)을 따릅니다.

- **2토큰 문맥이 승부처.** 카운트(2.65)를 넘은 건 v0.1.4/1.5(2.62) · v0.2.5(2.63) · v0.2.0(2.65) 뿐이고, 모두 2토큰 이상을 봐요.
  앞 1토큰만 보는 v0.1.0~1.3 은 4~6점대로 크게 뒤집니다 — 조사가 별도 토큰이라, 조사 하나만 보고 다음을 맞혀야 하는 자리가 생기거든요.
- **v0.1.3 은 '정규화가 항상 이득은 아니다'의 사례.** weight decay·label smoothing 을 켜도 v0.1.2 와 같은 4.04 —
  데이터가 쉽고 조기 종료가 이미 과적합을 막고 있으면 더 얹을 게 없어요.
- **v0.2.1/2.2 의 3점대를 '문맥이 넓어서'로 읽으면 안 돼요.** 두 버전은 문맥 말고 `EMBED`·`HIDDEN` 도 함께 줄였어요.
  원인은 **용량**입니다 — [🔬 한 번에 하나만 바꾸기](#-한-번에-하나만-바꾸기--ablation_block_sizepy) 참고.
- **임베딩은 효율과 일반화 둘 다.** 전체 PPL 은 v0.1.4 와 비슷하지만(2.63 vs 2.62) 파라미터는 **4.2분의 1**(166K vs 696K)이고,
  **처음 보는 자리**에선 one-hot 을 크게 앞서요 — 아래 캡스톤 결산 참고.

## 📏 여러 지표로 비교하기 — `eval_suite.py`

각 버전의 `2.test/test.py` 는 '그 버전 하나'를 봅니다. `eval_suite.py` 는 학습된 버전을
**모두 모아 같은 데이터로** 나란히 재요. 그리고 **지표를 하나만 보지 않습니다.**

```bash
python3 eval_suite.py                 # 학습된 버전 전부
python3 eval_suite.py v0.0.9 v0.2.0   # 고른 버전만
python3 eval_suite.py --quick         # 생성 지표는 느리니 건너뛰기
```

| 지표 | 묻는 것 |
|---|---|
| **PPL** (전체 / OOV 뺀 것) | 확률을 얼마나 잘 배분했나 |
| **top-1 / top-5 정확도** | 1등을 얼마나 맞혔나 |
| **후보 포함률** | 정답을 만들어낼 수 있기라도 한가 |
| **답 고르기 (Recall@1)** | 진짜 답을 가짜 답 9개 사이에서 고르나 |
| **생성 다양성 (distinct-1/2)** | 온도를 바꾸면 답이 실제로 다양해지나 |
| **파라미터 수 · 파일 크기** | 그 성능이 얼마짜리인가 |

실제로 재보면 **지표마다 승자가 다릅니다** — 이게 이 도구의 핵심 교훈이에요.

아래는 **산문 사전학습(`data/pretrain`)** 기준 결과예요.

조기 종료 기준은 **학습 손실 또는 검증 PPL 중 하나라도 개선되면 지속**(둘 다 patience=20 정체 시 종료),
저장하는 가중치는 **검증 PPL 이 가장 낮았던 에폭** = 일반화 최적점.

```
버전       종류     학습PPL  검증PPL   top-1   top-5   후보有     파라미터
v0.0.9   카운트     2.30    2.65    72.4%   84.3%   98.0%      8,883
v0.1.0   신경망     6.07    6.47    56.0%   72.5%   99.2%    232,456
v0.1.1   신경망     4.39    4.78    57.9%   75.5%   99.2%    232,456
v0.1.2   신경망     4.34    4.72    58.6%   75.4%   99.2%    464,008
v0.1.3   신경망     4.34    4.72    58.3%   75.6%   99.2%    464,008
v0.1.4   신경망     2.38    2.62    72.7%   84.5%   99.2%    696,201
v0.1.5   신경망     2.38    2.62    72.7%   84.5%   99.2%    696,201
v0.2.0   신경망     2.34    2.65    72.3%   84.4%   99.2%    595,593
v0.2.1   신경망     2.50    2.74    77.0%   84.5%   99.2%    158,121
v0.2.2   신경망     2.68    2.84    76.8%   84.8%   99.2%    158,121
v0.2.3   신경망     2.80    2.96    76.7%   84.2%   99.2%    166,025
v0.2.4   신경망     2.83    2.97    76.9%   84.1%   99.2%    166,025
v0.2.5   신경망     2.40    2.63    77.6%   85.0%   99.2%    166,025

→ 검증 PPL 최저 : 신경망 v0.1.4/1.5 = 2.62  ·  카운트(2.65)를 넘어섰어요
→ top-1 정확도 최고 : v0.2.5 = 77.6%   ← PPL 1등과 다릅니다
```

**결과 읽기**

- **상위권이 바짝 붙어 있어요.** v0.1.4/1.5(2.62) · v0.2.5(2.63) · v0.0.9 카운트(2.65) · v0.2.0(2.65) — 0.03 안에 네 모델.
- **격차는 근소.** 0.03 차이에 파라미터는 78배(69.6만 vs 8.9천). **이겼지만 압도하지 못했어요.**
- **문맥 길이가 승부처.** 앞 1토큰만 보는 v0.1.0~1.3 은 4점대로 크게 뒤집니다.
- **저장 지점이 성능을 만듦.** v0.1.4 의 학습 PPL 2.38 은 카운트(2.30)보다 **높은데** 검증 2.62 는 **낮아요** —
  마지막 에폭이 아니라 **검증 PPL 최저 에폭**(v0.1.4 는 epoch 12)의 가중치를 저장하기 때문.
  외운 양이 아니라 일반화가 이긴 겁니다.
- **v0.2.1/2.2 의 3점대는 문맥 탓이 아님.** 이 두 버전은 문맥과 함께 `EMBED`·`HIDDEN` 도 줄였어요.
  원인은 **용량** — [🔬 한 번에 하나만 바꾸기](#-한-번에-하나만-바꾸기--ablation_block_sizepy) 참고.
- **지표마다 승자가 다름.** 검증 PPL 1등은 v0.1.4(2.62), top-1 정확도 1등은 v0.2.5(77.6%).
  '확률을 잘 배분하는 것'과 '1등을 잘 맞히는 것'은 다른 능력이에요.
- **후보 포함률 97.1%(카운트) vs 98.9%(신경망).** 카운트는 표에 없는 조합을 아예 만들 수 없어요.
  PPL 에서는 `FLOOR` 가 메워 가려지는 한계입니다.
- **생성은 별개 문제.** 온도 0 에서는 PPL 1등인 v0.1.4 도 서로 다른 이어쓰기가 8% 뿐 —
  **PPL 이 좋다고 생성이 쓸 만하다는 보장은 없어요.** 온도를 올리면 90%대로 다양해지지만 엉뚱한 말이 늘어요.

> ⚠️ **v0.2.3/2.4 의 숫자는 실행마다 흔들려요.** 두 버전은 `EPOCHS` 가 cosine 스케줄의 감쇠 기간(`T_max`)을
> 겸하는 구조라, 1,500 으로 놓으면 학습률이 거의 안 줄어든 채 오래 머물러요. 그러면 **조기 종료가 언제
> 걸리느냐가 우연**이 됩니다 — 설정이 똑같은데도 v0.2.3 은 epoch 24, v0.2.4 는 42 에서 멈췄어요.
> **v0.2.5 가 `EPOCHS` 를 300 으로 낮춰 이걸 고쳤습니다** (epoch 279 까지 학습 → 2.96 → **2.63**).

> 이제 모든 버전이 루트 `data/pretrain` 을 공용하므로 데이터 지문이 같아 함께 비교돼요.
> (대화 전용 지표 '답고르기'는 산문엔 `<봇>` 이 없어 자동으로 `-` 로 표시됩니다.)
> 신경망 버전을 포함하려면 PyTorch 가 필요하고, 없으면 그 버전만 건너뜁니다.

## 🔬 한 번에 하나만 바꾸기 — `ablation_block_size.py`

대결표는 **버전끼리** 비교합니다. 그런데 버전 간에는 설정이 여러 개 한꺼번에 바뀌어서,
그것만으로는 "무엇이 원인인가"를 말할 수 없어요.

```bash
python3 ablation_block_size.py             # 2x2 전부 (MPS 로 약 30분)
python3 ablation_block_size.py --runs B C  # 고른 것만
```

**문제** — v0.2.0 → v0.2.1 은 `BLOCK_SIZE` 말고도 **5가지가 함께** 바뀐 비교

| 항목 | v0.2.0 | v0.2.1 |
|---|---|---|
| `BLOCK_SIZE` | 2 | 3 |
| `EMBED` | 256 | 32 (1/8) |
| `HIDDEN` | 256 | 128 (1/2) |
| `LR` | 0.0003 | 0.01 |
| `INIT` | zeros | default |
| `LABEL_SMOOTHING` | 0.0 | 0.1 |

**방법** — 나머지를 한 묶음으로 고정하고 `BLOCK_SIZE` 만 2↔3 으로 바꿔 4번 학습 (2×2).
A·D 는 기존 v0.2.0·v0.2.1 을 재현해야 하는 **온전성 검사**입니다.

**결과**

| 설정 묶음 | N=2 | N=3 | N 효과 | 파라미터 (N=2 → N=3) |
|---|---|---|---|---|
| v0.2.0 (E=256, H=256) | 2.6488 | **2.3675** | **−0.281** (좋아짐) | 595,593 → 661,129 |
| v0.2.1 (E=32, H=128) | 3.0586 | **2.7487** | **−0.310** (좋아짐) | 154,025 → 158,121 |

- **문맥 효과 −0.28 · −0.31** — 두 설정 모두 **넓힐수록 이득**, 부호가 일치해요.
- **용량 효과 0.40** — `EMBED`·`HIDDEN` 을 줄인 것. 문맥 효과와 **비슷한 크기**.
- ⇒ **v0.2.1 이 뒤진 건 문맥을 넓혀서가 아니라 용량을 줄여서.** 문맥 확장 자체는 오히려 이득이에요.
- 💡 문맥이 이만큼 이득인 건 **조사가 별도 토큰**이라서예요 — 토큰이 잘게 쪼개진 만큼
  같은 길이의 글을 담으려면 **더 많은 토큰**이 필요하거든요.
- 부수 확인: `BLOCK_SIZE=2` 는 v0.2.0 과 **완전히 동일**(2.6488 일치).

> 💡 **교훈: 한 번에 하나만 바꿔야 원인을 말할 수 있어요.**
> 이 저장소의 "버전 = 개념 한 걸음" 원칙이 바로 그 이야기인데, v0.2.1 은 그게 지켜지지 않은 예입니다.

> 학습된 모델을 **저장하지 않아요** — 기존 `0.model/` 산출물은 그대로입니다.

## 웹앱 실행

```bash
python3 web_service/server.py
```

브라우저에서 접속:

```
http://127.0.0.1:8000
```

- 우측 상단에서 **모델 버전** 선택 → 첫머리를 입력하면 그 버전이 **뒤를 이어 써(completion)** 줍니다.
- 산문으로 사전학습한 모델이라 **대화가 아니라 이어쓰기**예요 (대화 형식은 v0.5 SFT 부터).
- 온도 · top-k · top-p 슬라이더로 샘플링을 조절할 수 있어요.
- 학습이 끝난 버전(`0.model/model.json` 또는 `model.pt`)만 목록에 나타납니다.

## 모르는 단어가 입력되면?

입력의 **마지막 단어**가 시작점입니다. 그 단어를 모르면 시대별로 다르게 처리해요.

| | 마지막 단어를 아는 경우 | 모르는 경우 |
|---|---|---|
| **카운트 (v0.0.x)** | 그 단어부터 이어쓰기 | 아는 문맥 중 **무작위로 하나**를 골라 시작 |
| **신경망 (v0.1.x~)** | 그 단어부터 이어쓰기 | 문맥을 못 만들어 **즉시 중단** (빈 결과) |

- 어느 쪽이든 **오류 없이** 끝나지만, 카운트는 입력과 무관한 엉뚱한 문장이 나올 수 있어요.
- 단어의 *의미*를 이해하는 게 아니라 "무엇 다음에 무엇이 왔는지"만 배운 모델이기 때문입니다.

## v0.0.2·v0.0.3 에서 단어를 1개만 입력하면?

v0.0.2·v0.0.3 은 **앞 두 단어**로 다음 단어를 찾는 모델이에요. 그래서 입력이 1개뿐이면
두 단어짜리 문맥을 만들 수 없어, 다음 순서로 처리됩니다.

1. 마지막 두 단어가 필요한데 1개뿐 → 문맥을 못 만듦(빈 문맥)
2. 빈 문맥은 표에 없으므로 → **폴백**: 모델이 아는 두 단어 문맥 중 **무작위로 하나**를 골라 시작
3. 그 문맥부터 단어를 이어 붙여 문장을 완성 (v0.0.3 은 `<END>` 에서 자연스럽게 멈춤)

즉, **입력한 한 단어는 결과에 나오지 않고 무시**되며(무작위 시작), 시작 방식은 두 버전이 같고
**끝맺음만** 다릅니다(v0.0.2 는 툭 끊길 수 있고, v0.0.3 은 자연스럽게 마무리).

> ✅ **v0.0.4 부터 해결됨**: v0.0.4 의 **백오프**(앞 2단어가 없으면 1단어로 줄여 재시도) 덕분에,
> `"나는"` 한 단어만 입력해도 `"나는"` 으로 시작하는 문장을 만들 수 있어요. 더 이상 입력이 무시되지 않아요.

### 백오프 전후 비교 (1단어 `"나는"` 입력)

| 버전 | 1단어 "나는" 입력 결과 | 해석 |
|------|----------------------|------|
| v0.0.2 / v0.0.3 (백오프 X) | "단풍이 곱게 물듭니다" / "기분이 조금 나쁩니다" | 2단어 문맥 못 만들어 **입력 무시, 무작위 시작** |
| v0.0.4 / v0.0.5 / v0.0.6 (백오프 O) | "나는 아침에 밥을 먹습니다" 등 | 1단어로 줄여 찾아 **입력을 반영** ✅ |

## 새 버전을 만들려면?

1. **폴더 만들기** — `llm/<그룹>/<버전>/` (예: `llm/v0.2/v0.2.3/`) 아래에 `0.model` · `1.train` · `2.test`.
2. **`0.model/lm.py`** — 이전 버전을 `_load_prev("v0.2.2")` 로 상속하고, **이 버전이 바꾸는 함수만** 재정의.
3. **`1.train/train.py` 실행** — 학습 결과(`model.json` 또는 `model.pt` + `vocab.json`)가 생기면
   웹앱 목록과 `eval_suite.py` 에 **자동으로** 나타납니다.

> 이전 버전 폴더는 건드리지 않으니 **모든 단계가 그대로 보존**돼요 — 되돌아가 비교할 수 있습니다.
