# link_llm — 나만의 작은 언어 모델 (v0.2.1)

**문맥 확장 (`block_size`).** 2토큰 고정을 **앞 N토큰**으로 열어요.
각 토큰 임베딩을 이어붙여 MLP 에 넣는 = 진짜 **Bengio(2003) 입력층**.

## 한 걸음 — 문맥 길이를 설정값으로

| | v0.2.0 | v0.2.1 |
|---|---|---|
| 문맥 | 앞 2토큰 (고정) | **앞 N토큰** (`BLOCK_SIZE`) |
| 입력 | (B, 2) | (B, N) |
| 모델 | `Linear(2E, H)` | `Linear(N·E, H)` |
| 임베딩 concat | 2개 | **N개** (`emb(x).flatten(1)`) |

`BLOCK_SIZE=2` 로 두면 v0.2.0 과 **완전히 동일**합니다 (실측 검증 PPL 2.6488 일치).

## 구조

```
앞 N토큰 → 각 임베딩(E) → 이어붙임(N·E) → fc1 → tanh → fc2 → logits(V)
```

```python
class BlockModel(nn.Module):
    def __init__(self, V, H, E, block_size):
        self.emb = nn.Embedding(V, E)
        self.fc1 = nn.Linear(block_size * E, H)
        self.fc2 = nn.Linear(H, V)
    def forward(self, x):          # x: (B, N) 인덱스
        e = self.emb(x).flatten(1) # (B, N, E) → (B, N·E)
        return self.fc2(torch.tanh(self.fc1(e)))
```

## 문장 맨 앞 — `<PAD>`

- N토큰이 다 안 차는 문장 앞부분은 `<PAD>`(어휘 0번)로 채워요.
- 예) `ids=[a,b,c]`, N=3 → `(p,p,a)→b`, `(p,a,b)→c`, `(a,b,c)→<END>`

## 구현 — 최소 override

- 새로 정의: `build_net`(BlockModel) · `make_pairs`(N토큰) · `_context_ids`(앞 N토큰 인덱스 목록) · `load`(모양에서 N·E·H 복원)
- 그대로 상속: 임베딩 · 정규화 · 저장 · 대화 · PPL
- 새 하이퍼파라미터: **`BLOCK_SIZE`**(기본 3)

| | 검증 PPL | top-1 | 파라미터 |
|---|---|---|---|

### 이 숫자를 '문맥의 효과'라고 말할 수 있는 이유

이 버전은 **`BLOCK_SIZE` 하나만** v0.2.0 과 다릅니다. 나머지는 글자 하나까지 같아요:

| 항목 | v0.2.0 | v0.2.1 |
|---|---|---|
| `BLOCK_SIZE` | 2 | **3** ← 이것만 |
| `EMBED` | 256 | 256 |
| `HIDDEN` | 256 | 256 |
| `LR` | 0.0003 | 0.0003 |
| `INIT` | zeros | zeros |
| `LABEL_SMOOTHING` | 0.0 | 0.0 |

- 하나라도 같이 바꾸면 "문맥을 넓혀서 좋아졌다"를 말할 수 없어요 — 무엇이 원인인지 갈리지 않으니까요.
- 늘어난 파라미터는 **65,536개(+11%)** 뿐이에요:

  | | `emb`(V×E) | `fc1`(H×N·E) | `fc2`(V×H) | 합계 |
  |---|---|---|---|---|
  | v0.2.0 (N=2) | 231,680 | 131,072 | 231,680 | 595,593 |
  | **v0.2.1 (N=3)** | 231,680 | **196,608** | 231,680 | **661,129** |

  `N` 은 `fc1` 의 입력 폭 `N·E` 에만 나타나요 → **N 을 1 늘리면 딱 `H×E`(=65,536)개**만 늘어납니다.
  `emb`·`fc2` 는 그대로고요. **문맥 확장은 싼 개선**이에요.

### 왜 문맥이 이만큼 도움이 되나

v0.0.6 이 **조사를 별도 토큰**으로 떼어냈기 때문이에요.

```
"학교를 갔다"  →  [학교, ##를, 갔다]
```

`갔다` 를 맞히려 할 때 앞 2토큰은 `학교 ##를` 이지만, 앞 3토큰이면 그 앞 단어까지 봅니다.
**토큰이 잘게 쪼개진 만큼 같은 길이의 글을 담으려면 더 많은 토큰이 필요**해요.

**용량과 헷갈리지 않으려면** — 루트 `ablation_block_size.py` 가 2×2 로 다시 확인해요:

| 설정 묶음 | N=2 | N=3 | N 효과 |
|---|---|---|---|
| 큰 용량 (E=H=256) | 2.6488 | **2.3675** | **−0.281** |
| 작은 용량 (E=32, H=128) | 3.0586 | **2.7487** | **−0.310** |

- 두 묶음 **모두 넓힐수록 이득** — 부호가 일치해요.
- 용량 효과(0.40)는 문맥 효과와 비슷한 크기지만 **별개의 축**입니다.

> 💡 **한 번에 하나만 바꿔야 원인을 말할 수 있어요** — '버전 = 개념 한 걸음' 원칙이 바로 그 이야기입니다.
