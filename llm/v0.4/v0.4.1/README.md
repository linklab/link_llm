# v0.4.1 — 코퍼스·문서 패킹

> 문서를 출처와 함께 보존하고 중복·같은 주제/템플릿의 분할 누수를 막습니다. 여러 문서를 한 입력에 담아 학습하되 다른 문서의 내용을 볼 수 없게 합니다.

## v0.4.0에서 한 걸음 더

v0.4.0이 **글을 어떤 토큰으로 읽을지** 정했다면, v0.4.1은 **어떤 문서를 학습·평가에 쓸지, 문서를 어떻게 배치에 담을지** 정합니다.

| 항목 | v0.4.0 | v0.4.1 |
|---|---|---|
| 문서 저장 | 텍스트 파일의 LF 한 줄이 문서 | JSONL의 text 필드가 문서, 내부 문단 보존 |
| 데이터 기록 | 파일·문서 해시 | 출처·사용 조건·생성기 해시·주제·템플릿 추가 |
| 분할 | 기존 train/valid | 그룹을 분리한 train/valid/test |
| 중복 검사 | 현재 수정본은 원문 문서 교집합 검사 | NFC·공백 접기 비교 키로 제거, 원문은 보존 |
| 학습 입력 | 매 토큰 슬라이딩 문맥 | 정답을 중복하지 않는 청크 + 문서별 패킹 |
| 평가·생성 | 최근 32토큰 슬라이딩 | 같은 문맥 정책 유지 |

## 데이터에서 바뀐 점

- 이전 데이터는 그대로 두고 [문서 코퍼스](../../../data/pretrain/v0.4.1/README.md)를 추가했습니다. JSONL의 `text` 필드 하나가 문서 하나이므로 문단의 LF·CR·공백·Unicode가 보존됩니다.
- AI의 도움으로 작성한 12개 주제별 템플릿의 합성 산문 480개, train 320 / valid 80 / test 80입니다. 출처·MIT 사용 조건·생성 코드/원문 해시는 manifest에 기록합니다.
- 중복 비교 키는 NFC + 공백 접기를 사용하며 원문은 변경하지 않습니다. 중복 또는 같은 주제/템플릿으로 연결된 문서는 같은 split으로 배정합니다. 중복 제거 전 연결로 누수를 막습니다.
- 기본 valid는 텃밭·도서관, test는 시장·달리기 주제이며 학습에는 없는 주제/템플릿입니다. 이 그룹 정의는 작성한 메타데이터 기준입니다.
- BPE는 train만으로 학습하고, 조기종료는 valid만 사용합니다. train CLI는 test를 무결성 검사에만 사용하며 채점하지 않습니다.
- 테스트는 모델 선택 후 `--split test`로 별도 실행합니다. 코퍼스 manifest와 체크포인트의 해시를 확인하고 전체·긴 문서·주제별 지표를 기록합니다.

### 예시: 문단과 시험 문제를 보존하기

`첫 문단\n\n다음 문단`을 일반 줄 단위로 읽으면 문서 경계가 끊어집니다. JSONL에서는 다음 한 레코드의 `text` 전체를 문서 하나로 읽습니다.

```json
{"id":"garden-000","text":"첫 문단\n\n다음 문단","source":"authored-v041","topic":"garden","template_id":"garden-journal-v1"}
```

또한 ‘민수의 텃밭 수첩’과 ‘지우의 텃밭 수첩’처럼 이름만 바꾼 같은 템플릿을 학습과 시험에 나누면, 처음 보는 글을 이해하는 능력보다 이미 외운 문장 틀을 재는 셈이 될 수 있습니다. v0.4.1은 이런 문서를 같은 그룹에 둡니다.

| 용도 | 문서 수 | 사용 방법 |
|---|---:|---|
| train | 320 | BPE 병합 규칙과 신경망을 학습 |
| valid | 80 | 학습 중 성능 확인·최저 PPL 모델 선택 |
| test | 80 | 모델 선택이 끝난 뒤 고정 모델을 별도 채점 |

중복 비교에서는 `가`와 분해형 `가`, `a b`와 `a  b`를 같은 것으로 취급합니다. **비교용 키만 정리하고 저장할 원문은 바꾸지 않습니다.** 중복 문서를 없애기 전에 주제·템플릿 연결 관계를 기록하므로, 제거 때문에 분할 누수를 놓치지 않습니다. 실제 기본 코퍼스의 중복 제거 수는 0개이며, 제거 동작은 별도 테스트로 확인했습니다.

## 패킹을 예시로 이해하기

문서 A가 토큰 `a, b`, 문서 B가 `c`로 구성됐다고 가정합니다. 문맥 크기가 충분하면 둘을 한 행에 담습니다.

```text
입력:       BOS   a   b  | BOS   c
정답:        a    b  EOS |  c   EOS
문서 번호:   0    0   0  |  1    1
위치 번호:   0    1   2  |  0    1
```

- 정답 `c`를 예측하는 문서 B의 BOS 위치는 자기 문서의 BOS만 참조합니다. 이어서 EOS를 예측하는 입력 `c` 위치는 BOS와 자기 자신을 볼 수 있습니다. 두 위치 모두 문서 A는 attention mask로 차단됩니다.
- EOS 다음 문서의 BOS를 맞히는 가짜 정답을 만들지 않습니다. 각 문서의 첫 토큰과 EOS는 정확히 한 번 학습합니다.
- 빈 문서는 BOS→EOS 1자리입니다. 남는 배치 공간에는 PAD를 넣고 정답을 -100으로 채워 손실에서 제외합니다.
- 위치 번호는 각 문서 청크에서 0부터 다시 시작합니다. 패킹된 logits는 같은 청크를 따로 실행한 logits와 수치 허용오차 내 일치합니다(dropout을 끈 평가 모드 기준).

## 긴 문서와 평가 계약

학습에서는 문서를 문맥 길이만큼의 **겹치지 않는 정답 청크**로 나눕니다. 예를 들어 문맥 3, 문서 토큰이 `a b c d e`이면:

```text
첫 청크 입력: BOS a b    정답: a b c
다음 청크 입력: c d e    정답: d e EOS
```

두 번째 청크는 앞 청크의 마지막 정답 `c`를 입력으로 사용합니다. 문서 중간에 BOS/EOS를 새로 끼우지 않고, 마지막에만 EOS를 학습합니다. 청크 간 attention과 상태 공유는 없습니다.

**학습 문맥은 v0.4.0의 매 토큰 슬라이딩 문맥과 다릅니다.** 반복 계산을 줄이는 대신 청크 첫 부분에서 사용할 수 있는 과거 문맥이 짧아집니다. 패킹을 했다는 이유만으로 같은 학습 목적·같은 품질이라고 주장하지 않습니다.

평가·생성은 v0.4.0의 최근 32토큰 슬라이딩 문맥을 그대로 사용합니다. 첫 토큰과 EOS를 채점하고 확률 하한 없이 NLL을 계산합니다. 원문 바이트당 NLL에서는 EOS 비용을 제외하고 별도 보고합니다. 평가에서는 다른 문서의 과거 문맥을 사용하지 않습니다.

## 기본 CPU 실행 결과 (시드 1234)

4층·4헤드·E=64·FFN=256·문맥 32·어휘 768·dropout 0.1, Adam 0.003·배치 128·최대 30에폭·patience 5입니다. 모델 파라미터는 300,160개입니다.

| 지표 | validation | held-out test |
|---|---:|---:|
| 문서 | 80 | 80 |
| 원문 바이트 | 38,356 | 39,416 |
| 정답 토큰 (EOS 포함) | 16,136 | 16,646 |
| 토큰 PPL | 141.249383 | 157.648355 |
| 원문 NLL/byte | 2.072057 | 2.127387 |
| bits/byte | 2.989346 | 3.069171 |
| top-1 | 25.57% | 25.15% |

- 검증 최저 epoch 5를 선택하고 epoch 10에서 종료했습니다. [학습 보고서](0.model/training_report.json), [저장본 검증 평가](0.model/valid_report.json), [고정 모델 테스트 평가](0.model/test_report.json)에 원시 수치를 남겼습니다.
- 보고서의 학습 루프 시간은 약 37.36초(에폭별 검증 포함), 저장·최종 train/valid 평가까지는 약 49.01초입니다. 단일 실행의 경과 시간이며 다른 버전과의 통제된 속도 비교가 아닙니다.
- train 에폭당 정답 48,680개, 패킹 행 1,698개, 최대 용량 대비 채움률 89.59%입니다. 같은 토큰열을 기존 슬라이딩 창으로 학습하면 입력 토큰 계산이 1,240,320개, 현재 청크 패킹은 48,680개입니다. **25.48배는 입력 토큰 수의 비율이지 실측 속도 향상 배수가 아닙니다.**
- 모든 데이터 문서는 현재 BPE 문맥 32보다 깁니다. `long_documents` 지표가 전체 지표와 같은 이유입니다. 여러 문서를 실제로 같은 행에 담는 짧은 문서 사례는 자동 테스트에도 포함합니다.
- 저장본 평가 결과는 학습 보고서와 일치합니다. 코퍼스 전체 480개 원문 복원과 데이터 파일/manifest의 바이트 단위 재생성, train-only BPE 재학습 일치를 확인했습니다.

## 검증과 수정

- v0.4.1 자동 테스트 16개: 청크 경계·모든 정답 1회, 독립 청크와 logits 일치, 문서 간 attention/gradient 격리, 인과성·PAD·특수 출력 마스크, 저장 복원·구버전 평가 일치, train-only BPE, 재현 가능한 그룹 분할·정규화 중복 제거, 손상 데이터·누수 거부, 특수 Unicode 줄 구분자 보존, CLI 학습/재평가/테스트, 웹 입력, v0.4.0 중복 검사 회귀.
- v0.4.0 테스트 12개와 v0.3.4 테스트 16개도 통과했습니다.
- v0.4.0 P2 두 건을 수정했습니다. 학습 CLI는 파싱한 원문 문서의 교집합을 검사하므로 마지막 LF만 다른 동일 문서도 거부합니다. 웹은 원문을 그대로 전달하고, 이를 지원하는 BPE 모델은 빈 입력에서 BOS로 생성합니다. 구형 모델의 trim·빈 입력 거부 동작은 유지합니다.
- 실제 웹 로더의 v0.4.1 검색·저장 모델 로드·일반/공백/빈 입력 생성과 요청 핸들러 경로를 확인했습니다. 브라우저 화면 전체나 원격 접속까지 검증한 것은 아닙니다.

## 한계

- 이번 버전은 데이터·학습 파이프라인 구현입니다. 12개 템플릿의 작은 합성 코퍼스라 이름·시간 변형이 많고 일반화가 제한됩니다. 정규화 중복 제거는 의미적 유사 중복 탐지가 아닙니다.
- **생성 품질은 아직 낮습니다.** 고정 프롬프트 ‘오늘은’에서 ‘오늘은 위 ��다시 다시 수 수 …’처럼 반복·깨진 UTF-8이 나왔고 빈 프롬프트에서는 공백만 반복했습니다. 체크포인트와 평가 보고서에 결과를 그대로 남겼습니다. 입력의 가역성과 생성 문장의 품질은 별개입니다.
- 새 코퍼스·새 분할·새 BPE이며 학습 문맥 정책도 변경됐으므로 v0.4.0의 PPL 1.747033과 직접 비교할 수 없습니다. 단일 시드의 작은 주제 분할 결과를 일반 언어 능력으로 해석하지 않습니다.
- 긴 문서를 저장·분할하지만 32토큰을 넘는 장거리 의존을 직접 학습하는 모델은 아닙니다. 문맥 확장은 v0.4.3, KV 캐시는 v0.4.4 범위입니다.
- optimizer/RNG를 포함한 학습 재개, AdamW·warmup·cosine·gradient clipping은 v0.4.2에서 다룹니다.

## 실행

저장소 루트에서 PyTorch가 설치된 Python으로 실행합니다. 이 환경에서는 `conda activate link_llm`을 사용합니다.

```bash
# 코퍼스 재생성 (기존 버전 데이터는 유지)
python data/pretrain/v0.4.1/generate.py
# 자동 테스트
python llm/v0.4/v0.4.1/2.test/test_invariants.py
# 기본 설정 학습·최저 검증 가중치 저장
python llm/v0.4/v0.4.1/1.train/train.py --device cpu
# 저장 모델·데이터 해시 확인과 검증 평가
python llm/v0.4/v0.4.1/2.test/test.py --split valid
# 모델 선택을 끝낸 후 테스트 평가 (이 점수로 다시 선택하지 않기)
python llm/v0.4/v0.4.1/2.test/test.py --split test \
  --output-report llm/v0.4/v0.4.1/0.model/test_report.json
python web_service/server.py
```

별도 코퍼스는 `--corpus-dir`, 별도 실험 모델은 학습의 `--output-dir`과 평가의 `--model`로 지정합니다. 다른 코퍼스 평가는 `--allow-new-data`를 명시해야 하며, 이때도 코퍼스 내부 중복·분할 검사와 체크포인트/학습 보고서 일치 검사는 유지합니다. 기본 출력 경로로 재학습하면 기존 모델·보고서를 갱신합니다. 가중치·vocab.json은 Git 제외이므로 다른 컴퓨터에서는 재학습하거나 별도 전달해야 합니다.
