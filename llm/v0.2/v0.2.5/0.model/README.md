# 0.model 폴더 (v0.2.5)

- `lm.py` : 이 버전 코드. v0.2.4 를 **그대로** 물려받고, **3자 비교 도구**를 더했어요.
- `model.pt` · `vocab.json` : 학습 결과 (`1.train/train.py` 실행 시 생성). **torch 환경에서 학습해야 생겨요.**

## 이 버전 모델의 특징

**새 개념:** 모델이 아니라 **'질문'** — 임베딩 시대를 열며 내건 약속을 실제로 재는 캡스톤.

모델·학습·저장은 v0.2.4 그대로예요 (`class NeuralLM(_prev.NGramLM): pass`).
v0.2.5 가 더하는 건 v0.2.0 이 내건 주장을 검증하는 도구입니다.

> "one-hot 은 처음 보는 조합에 무력하지만, 임베딩은 비슷한 토큰이 비슷한 벡터라
> **처음 보는 조합에도 일반화**한다."

## 왜 v0.1.5 의 대결표로는 부족한가

v0.1.5 는 버전마다 **검증 PPL 하나**를 냈어요. 그런데 그 숫자는

- 학습에서 **본 조합**(외우기만 해도 맞히는 자리) 과
- **처음 보는 조합**(일반화가 필요한 자리) 을

**섞어서 평균**낸 값이에요. 이 데이터에선 앞쪽이 96% 라, 뒤쪽에서 무슨 일이 벌어져도
평균에 거의 안 나타납니다. **그래서 자리를 나눠서 재요.**

## 도구

```python
load_version_model("v0.0.9")                     # 다른 버전 학습 결과를 그 버전 클래스로 로드
token_logprobs(lm, sentences)                    # 채점 자리마다 log p(정답) 하나씩
novelty_buckets(reader, train, valid)            # 자리마다 ①②③ 이름표 (모델과 무관)
bucket_ppl(logps, labels)                        # 칸별 PPL = exp(-평균 log p)
compare(reader, train, valid, versions)          # 3자 대결 → (rows, skipped)
param_count(lm)                                  # 신경망은 텐서 원소 수, 카운트는 표의 칸 수
```

### `token_logprobs` — PPL 을 자리별로 쪼개기

`perplexity()` 는 `exp(-평균 log p)` 로 **숫자 하나**만 돌려줘요.
칸별로 다시 재려면 **평균 내기 전의 log p** 가 필요해서, 같은 계산을 자리별로 남깁니다.

| 모델 | 방식 |
|---|---|
| 카운트 | `token_prob()` 를 자리마다 — 표 찾기라 빨라요 |
| 신경망 | `perplexity()` 와 똑같이 **한 번에 배치로** (자리마다 부르면 GPU 왕복으로 수십 배 느림) |

- 같은 `FLOOR` 로 눌러 `log(0)` 을 막고, 합산은 **CPU 배정밀도**로 해요 (MPS 에 float64 없음).
- 검증: `exp(-평균)` 이 그 버전 `perplexity()` 와 **소수점 15자리까지 일치**합니다.

### `novelty_buckets` — 이름표는 데이터만 보고 붙여요

학습 문장에서 `(앞 2토큰, 다음 토큰)` 을 모아 둔 뒤, 검증 자리를 그 집합과 대조할 뿐이에요.
**모델을 전혀 안 봅니다.**

| 칸 | 조건 | 뜻 |
|---|---|---|
| ① `본 조합` | `(문맥, 다음토큰)` 이 학습에 있었음 | 외우기만 해도 맞힘 |
| ② `새 조합` | 문맥은 봤지만 그 조합은 처음 | ★ 일반화가 필요 |
| ③ `새 문맥` | 문맥 자체가 처음 | ★★ 가장 어려움 |

## 왜 문맥을 2토큰으로 잡았나 (`NOVELTY_CONTEXT = 2`)

세 모델의 문맥 길이가 서로 달라요 — 카운트 최대 2 · one-hot 2 · 임베딩 3.
판정 기준을 어느 한 모델의 길이에 맞추면 **그 모델에 유리한 자로 재는 셈**이 됩니다.

그래서 셋의 **공통 분모인 앞 2토큰**을 썼어요. 판정이 모델과 무관해야
"임베딩이 처음 보는 자리에서 강하다" 를 공정하게 말할 수 있습니다.

## 공정한 비교인 이유

- 세 모델 모두 같은 토크나이저(punct) · 같은 `prepare`(`<END>`) · 같은 `FLOOR`.
- 채점 자리도 같아요 — `scored_positions()` 하나로 뽑아 **순서까지 맞춥니다**.
- 자리 수가 어긋나면(토크나이저가 다른 옛 버전) 그 버전을 **건너뛰고** 이유를 알려줘요.
- 임베딩 쪽만 더 손보지 않으려고 `1.train/train.py` 설정을 **v0.2.4 와 똑같이** 뒀어요.

## 저장 형식 — v0.2.4 와 동일

| 파일 | 내용 |
|---|---|
| `model.pt` | 가중치 `state_dict` (weight tying 이라 `fc2.weight` 는 빼고 저장) |
| `vocab.json` | `{ tokenizer, vocab }` — 어휘 목록 (0번 = `<PAD>`) |

- 카운트(v0.0.x)는 `model.json`(개수 표) — `load_version_model()` 이 알아서 구분해요.
