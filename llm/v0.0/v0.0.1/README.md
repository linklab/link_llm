# link_llm — 나만의 작은 언어 모델 (v0.0.1)

신경망 없이 **"단어를 세는 것"** 만으로 문장을 만드는 언어 모델이에요. (Python 3 만 있으면 실행)

## 언어 모델이 뭐예요?

언어 모델은 **"이 단어 다음에는 어떤 단어가 나올까?"** 를 맞히는 프로그램이에요.
휴대폰 자판에서 다음 단어를 추천해 주는 기능과 비슷해요.

우리 모델의 원리는 딱 두 줄로 정리돼요:

1. **학습**: 문장들을 보고 "어떤 토큰 뒤에 어떤 토큰이 몇 번 나왔는지" 표를 만든다.
2. **생성**: 그 표를 보고 가장 자주 나온 토큰을 계속 이어 붙여 문장을 만든다.

## 그 전에 — 무엇을 '한 개'로 셀까? (토크나이저)

세려면 먼저 **텍스트를 토막 내야** 해요. 이 토막이 **토큰**이고, 토막 내는 규칙이
**토크나이저**입니다. 언어 모델이 세상을 보는 **최소 단위**라, 여기서 정한 게 끝까지 따라와요.

v0.0.1 은 가장 단순한 규칙을 씁니다 — **띄어쓰기로만 자르기**.

```python
def tokenize(self, text):      return text.split()          # "나는 학교를" -> ["나는", "학교를"]
def detokenize(self, tokens):  return " ".join(tokens)      # 다시 문장으로
def tokenizer_name(self):      return "whitespace"          # 저장 파일에 기록
```

**이건 '당연한 것'이 아니라 하나의 선택이에요.** 그래서 세 함수로 따로 빼 뒀고,
뒤 버전에서 **통째로 갈아끼웁니다**. 지금 규칙엔 이런 손해가 있어요:

| 문제 | 예 | 언제 고치나 |
|---|---|---|
| 문장부호가 단어에 붙음 | `좋아!` 와 `좋아` 가 **다른 토큰** | v0.0.6 |
| 조사가 단어에 붙음 | `학교를` `학교는` `학교에` 가 **서로 무관한 세 토큰** | v0.0.6 |

두 번째가 한국어에선 특히 아파요. 한국어는 **교착어**라 명사 뒤에 조사가 달라붙거든요.
`tokenizer_name()` 을 모델 파일에 함께 저장하는 이유도 여기 있어요 —
**자르는 규칙이 다르면 두 모델은 애초에 비교할 수 없기 때문**입니다.

## 폴더 구조

```
v0.0.1/
├── 0.model/         # 모델 코드와 결과가 있는 곳
│   ├── lm.py       #   - NGramLM(기능) + Model(설정 ORDERS=[1]) — 뒤 버전들이 물려받음
│   └── model.json  #   - train.py 를 실행하면 자동으로 생겨요
├── 1.train/          # 학습(공부)시키는 곳
│   └── train.py    #   - 얇은 실행기 (실제 학습 코드는 0.model/lm.py)
└── 2.test/           # 만든 모델을 시험해 보는 곳
    └── test.py     #   - 얇은 실행기 (실제 생성 코드는 0.model/lm.py)
```

> v0.0.1 은 언어 모델의 **기반 클래스** `NGramLM` 을 [`0.model/lm.py`](0.model/lm.py) 에 통째로 담아요.
> 뒤 버전들(v0.0.2 ...)은 이 클래스를 물려받아 **바뀌는 함수만** 자기 `0.model/lm.py` 에 덧붙입니다.

## 사용 방법

준비물: **Python 3** (추가 설치 필요 없음! 기본 기능만 사용해요.)

### 1단계 — 학습시키기

```bash
python3 1.train/train.py
```

실행하면 `0.model/model.json` 파일이 만들어져요.

### 2단계 — 문장 만들어 보기

```bash
python3 2.test/test.py
```

배운 문장을 바탕으로 새 문장을 만들어 보여줍니다.
