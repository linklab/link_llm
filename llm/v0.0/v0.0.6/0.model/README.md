# 0.model 폴더 (v0.0.6)

학습이 끝난 **모델 파일(`model.json`)** 이 저장되는 곳이에요.
(`1.train/train.py` 를 실행하면 자동으로 만들어집니다.)

## 이 버전 모델의 특징

**새 개념:** 모델이 아니라 **토크나이저** — 텍스트를 어떤 단위로 자를지 정하는 규칙.

- **문맥 길이:** 앞 1토큰 + 2토큰 (`max_order = 2`, 표 `"1"`, `"2"`)
- **토크나이저:** **`punct+josa`** ← v0.0.5(`whitespace`) 와의 핵심 차이
- **문장 끝(`<END>`):** 학습함

## 토크나이저가 하는 일 — 두 단계

```python
tokenize("오늘은 학교를 갔다.")
# ① 문장부호 분리 → ["오늘은", "학교를", "갔다", "."]
# ② 조사 분리     → ["오늘", "##은", "학교", "##를", "갔다", "."]
```

| 함수 | 하는 일 |
|---|---|
| `tokenize(text)` | ① 문장부호를 떼고 ② 각 단어에서 조사를 떼요 |
| `split_josa(word)` | 단어 하나를 `[어간, ##조사]` 로. 겹조사는 **재귀**로 (`오후에는` → 오후 + ##에 + ##는) |
| `detokenize(tokens)` | 문장으로 되돌려요. `##` 조각과 문장부호는 앞 토큰에 딱 붙임 |
| `tokenizer_name()` | `"punct+josa"` — 저장 파일에 기록 |

## 설정값

| 이름 | 값 | 뜻 |
|---|---|---|
| `SUFFIX_MARK` | `"##"` | 앞 토큰에 붙는 조각 표시 (BERT/WordPiece 방식) |
| `JOSA` | 19종 | 떼어낼 조사. **긴 것부터** 봐야 `에서` 를 `에`+`서` 로 잘못 안 잘라요 |
| `MIN_STEM` | `2` | 어간이 이보다 짧아지면 자르지 않음 |
| `NO_SPLIT` | 53개 | 규칙 예외 목록 (아래) |

## 규칙을 짤 때 걸린 함정 세 가지

**① 긴 조사가 실패하면 짧은 조사로 내려가면 안 돼요**

```
곁으로 → "으로" 매치 → 남는 건 "곁"(1글자) → MIN_STEM 미달
       → 여기서 "로" 로 내려가면 "곁으" + ##로  ❌
       → 그래서 실패하면 그냥 멈추고 통째로 둡니다
```

**② 겹조사는 재귀로 풀어요**

```
오후에는 → 오후에 + ##는 → (재귀) 오후 + ##에 + ##는  ✅
```

**③ 재귀가 명사까지 파고들 수 있어요**

```
거북이가 → 거북이 + ##가 → (재귀) 거북 + ##이 + ##가  ❌
```

`거북이`·`고양이`·`떡볶이`·`태권도` 처럼 **조사처럼 끝나지만 그게 단어의 일부**인 명사는
`NO_SPLIT` 에 넣어 재귀를 멈춥니다.

## `NO_SPLIT` — 규칙 기반의 한계가 드러나는 곳

| 종류 | 예 | 왜 |
|---|---|---|
| 동사·형용사 관형형 | `뛰어노는` `돌아오는` `맛있는` | 어간이 동사라 자르면 `뛰어노` 같은 조각이 생김 |
| 부사 | `느지막이` `틈틈이` `저절로` | 끝의 `이`/`로` 가 조사가 아님 |
| 조사처럼 끝나는 명사 | `거북이` `고양이` `오랜만` | 그 글자가 단어의 일부 |

**목록이 필요하다는 사실 자체가 결론**이에요 — 규칙으로는 예외를 다 못 막습니다.
그래서 **v0.4.0 에서 데이터로 직접 배우는 BPE** 로 넘어가요.

## 검증

- **왕복 복원**: 학습·검증 4,000문장 전부 `detokenize(tokenize(s)) == s` (실패 0건)
- **겹조사 분리**: 코퍼스 전체에서 2건뿐이고 둘 다 정답 (`오후에는`, `겨울에는`)

## model.json 예시

```json
{
  "max_order": 2,
  "tokenizer": "punct+josa",
  "tables": {
    "2": { "학교 ##를": { "갔다": 3 }, "좋습니다 !": { "<END>": 1 } },
    "1": {
      "학교": { "##를": 12, "##에": 9, "##에서": 4 },
      "!": { "<END>": 15 },
      "?": { "<END>": 11 }
    }
  }
}
```

두 가지가 눈에 띄어요:

- `"학교"` 뒤에 **여러 조사가 후보로 모입니다.** 조사를 안 나눴다면 `학교를`·`학교에`·`학교에서` 가
  각각 딴 칸에 흩어져, 세어 놓은 횟수를 서로 나눠 쓸 수 없었어요.
- `"!"` 나 `"?"` 뒤에는 거의 항상 `"<END>"` — 문장부호가 문장을 끝맺는 신호라는 걸 배운 거예요.

## 왜 `tokenizer` 를 파일에 저장하나

**자르는 규칙이 다르면 두 모델은 비교할 수 없어요.** PPL 은 '토큰당' 평균이라
단위가 다르면 숫자의 뜻 자체가 달라집니다. 루트 `eval_suite.py` 가 이 값을 확인해
규칙이 다른 버전은 대결표에서 자동으로 빼줍니다.
