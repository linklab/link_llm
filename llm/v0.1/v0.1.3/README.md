# link_llm — 나만의 작은 언어 모델 (v0.1.3)

**정규화 · 초기화.** 모델·데이터·옵티마이저는 v0.1.2 그대로이고, **목표**가 바뀝니다 —
손실을 더 낮추는 게 아니라 **일반화(검증 PPL) 개선**.

## 한 걸음 — 과적합을 눌러 '처음 보는 것'에 강하게

| # | 더한 것 | 코드 | 왜 |
|---|---|---|---|
| ① | **weight decay (L2)** | `Adam(..., weight_decay=1e-4)` | 큰 가중치에 벌점 → 분포가 부드러워짐 |
| ② | **초기화** | `nn.init.zeros_(model.fc2.weight)` | 마지막 층을 0 으로 → 처음엔 '균등 확률'에서 출발 |
| ③ | **label smoothing** | `F.cross_entropy(..., label_smoothing=0.1)` | 정답 과신↓ → 일반화 |

## 성적 — 이득이 없습니다 (정직한 결과)

| 버전 | 검증 PPL | 채택 에폭 |
|---|---|---|
| v0.1.2 (정규화 없음) | 4.0429 | 18 |
| **v0.1.3 (정규화 켬)** | **4.0432** | 18 |

- 두 값이 **사실상 동일**하고, 최적 에폭도 같아요.
- 이유: 데이터가 쉽고, **조기 종료가 이미 과적합을 막고 있어서** 더 얹을 게 없습니다.
- 교훈: **정규화가 항상 이득은 아니에요.** 켤 이유(과적합)가 있어야 값을 합니다.
- 이 도구들의 진가는 **더 크고 어려운 데이터**(v0.5 SFT · v0.4 스케일업)에서 드러나요.

> ⚠️ **강하게 걸면 오히려 손해.** 이 크기 모델엔 `weight_decay` 를 키우면 underfit 이 납니다.
> 현재 기본값은 `WEIGHT_DECAY=0.0` · `LABEL_SMOOTHING=0.1` — **label smoothing 이 주 정규화**예요.

## 실행

> ⚠️ **PyTorch** 필요: `pip install torch`

```bash
python3 1.train/train.py     # 정규화·초기화로 학습 → 0.model/model.pt (+ vocab.json)
python3 2.test/test.py       # 학습/검증 PPL 격차 + 이어쓰기 예시
```

`WEIGHT_DECAY` 를 0 ↔ 1e-4 로, `LABEL_SMOOTHING` 을 0 ↔ 0.1 로 바꿔 비교해 보세요.
