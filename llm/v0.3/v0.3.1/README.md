# v0.3.1 — 멀티헤드 어텐션

## 한 줄 요약

> 하나의 어텐션을 여러 헤드로 나누어 계산한 뒤, 결과를 이어붙이고 출력 projection으로 섞습니다.

## 왜 필요한가?

- 단일 헤드가 한 가지 가중합을 만드는 데서, 여러 가중합을 병렬로 학습하도록 확장합니다.
- 예를 들어 서로 다른 헤드가 앞 문맥의 서로 다른 단서에 가중치를 줄 수 있습니다. 특정 헤드가 반드시 문법이나 의미를 담당한다는 보장은 없습니다.
- Notion v0.3.1 계획의 **헤드 분할·병합·출력 projection·마스크 유지**를 구현합니다. 위치 임베딩은 v0.3.2에 남깁니다.

## 무엇이 바뀌었나?

- 기본 `HEADS=4`, 전체 임베딩 `E=64`, 헤드 차원 `D=E/H=16`입니다. 전체 임베딩 크기를 헤드 수만큼 늘리지 않습니다.
- Q/K/V 출력 `(B,T,E)`를 `(B,H,T,D)`로 나누고, 각 헤드에서 `sqrt(D)`로 스케일링합니다.
- 결과를 `(B,T,E)`로 연결한 뒤 `Linear(E,E, bias=False)` 출력 projection을 거칩니다.
- `--heads`로 헤드 수를 지정합니다. 양수 정수이고 임베딩 차원을 나누어떨어지게 해야 합니다.
- 헤드 수는 가중치 모양만으로 알 수 없으므로 체크포인트 메타데이터에도 저장하고 로드 시 복원합니다.
- v0.3.0에 신경망 생성·추가 메타데이터 확장 지점을 추가했습니다. 기존 가중치 형식과 기본 동작은 유지하며, v0.3.1은 학습·데이터·생성·평가를 그대로 상속합니다.

## 모델 내부 구조

```text
tokens (B,T) → Embedding (B,T,64)
 → Q/K/V Linear(64,64)
 → 각 텐서를 (B,4,T,16)으로 분할
 → softmax(QKᵀ / sqrt(16) + causal/PAD mask)
 → weights @ V (B,4,T,16)
 → 헤드 연결 (B,T,64)
 → 출력 projection Linear(64,64)
 → 어휘 출력 Linear(64,V) → logits (B,T,V)
```

- 각 헤드는 현재와 과거의 실제 토큰만 볼 수 있습니다. all-PAD 입력도 NaN이 되지 않게 처리하고 PAD는 생성 후보에서 제외합니다.
- 위치 정보·residual·LayerNorm·FFN·dropout·KV 캐시는 추가하지 않았습니다.
- 파라미터 수는 `2VE + 4E² + V`입니다. 같은 V/E의 v0.3.0보다 projection의 `E²`만큼 증가합니다. 헤드 수만 바꾸면 파라미터 수는 같지만 계산 방식은 달라집니다.

## 효과와 검증

기본 설정 CPU 실측: **133,129 파라미터**, 검증 **PPL 3.2256**, **top-1 74.44%**,
top-5 82.12%, coverage 95.53%, 채점 10,197자리입니다. epoch 18을 채택하고
28에폭에서 조기종료했습니다. 학습·최종 평가 시간은 이 환경에서 약 55초입니다.
v0.3.0 저장본 PPL 3.2405 대비 소폭 낮지만, 단일 실행이며 projection도 추가되어
헤드 수만의 개선이나 통계적으로 유의한 우위를 의미하지 않습니다.

- v0.3.0의 인과 마스크, PAD/손실, 정답 이동, OOV, 저장/로드, 작은 배치 과적합, 조기종료 복원 검증을 유지합니다.
- 헤드 1개와 항등 projection은 같은 가중치의 v0.3.0과 일치합니다.
- 벡터화한 헤드 계산을 독립된 헤드별 행렬곱과 대조합니다. Q/K/V의 각 헤드와 출력 projection에 gradient가 전달됩니다.
- 기본값과 다른 헤드 수의 저장/로드, 잘못된 헤드 수 거부, 버전이 다른 체크포인트 거부를 검사합니다.
- CPU 기반 테스트에서 복원 모델도 CPU를 명시하므로 자동 MPS 선택과 CPU 입력이 섞이지 않습니다.
- 실측 설정·데이터 해시·환경·결과는 `0.model/training_report.json`에 기록됩니다. 기존과 같은 합성 산문 3,600/400문장 및 FLOOR 평가 규칙을 사용합니다.

## 한계

- 위치 임베딩 이전의 교육용 중간 단계입니다. 여러 헤드만으로 순서 이해를 완성했다고 보지 않습니다.
- 출력 projection도 함께 추가되므로 v0.3.0과의 성능 차이를 헤드 수만의 효과로 해석하지 않습니다. 분리 실험은 v0.3.1에서 `--heads 1`과 `--heads 4`를 비교할 수 있습니다.
- 단일 시드 검증 수치는 모델 선택에 사용한 결과이며, 독립 테스트나 반복 실험에 의한 일반화 보장이 아닙니다.
- OOV 처리·긴 문장의 슬라이딩 비용·산문 모델의 대화 한계는 v0.3.0과 같습니다.
- 모델 파일은 추론용 가중치·설정이며 optimizer/RNG까지 복원하는 학습 재개는 아직 제공하지 않습니다.

## 실행

저장소 루트에서 PyTorch가 설치된 Python으로 실행합니다.

```bash
python llm/v0.3/v0.3.1/2.test/test_invariants.py
python llm/v0.3/v0.3.1/1.train/train.py --device cpu --heads 4
python llm/v0.3/v0.3.1/2.test/test.py --prompt "오늘은"
python eval_suite.py v0.3.0 v0.3.1 --quick
python web_service/server.py
```

학습 후 `model.pt`가 있는 컴퓨터에서만 웹앱 목록에 표시됩니다. 가중치는 기존 Git 제외 규칙을 따르므로 다른 컴퓨터에서는 재학습하거나 모델 파일을 별도로 복사해야 합니다.
