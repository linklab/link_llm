# v0.4.3 — 문맥·규모 확장

**한 번에 읽는 길이를 32→64토큰, 폭을 64→96, 층을 4→6으로 늘렸습니다.** 기본 학습량도 6→8에폭으로 늘립니다. 설정으로 더 긴 문맥을 실험할 수 있지만, 실제 검증 범위는 64토큰입니다.

입력 임베딩과 출력 가중치를 공유합니다(**weight tying**). 예를 들어 같은 단어장을 “읽기용”과 “쓰기용”으로 두 벌 만드는 대신 한 벌을 함께 씁니다. 두 경로의 gradient가 같은 파라미터에 모이며, 공유 여부는 저장·재개 때도 보존합니다.

## 한 축씩 바꾼 CPU 비교

같은 데이터·train-only BPE·시드·AdamW 설정으로 인접 행에서 한 축만 바꿉니다. FFN 폭은 비교에서 256으로 고정합니다. 문맥 변경은 패킹 행 수와 업데이트 수까지 바꾸므로 완전한 동등 계산량 비교는 아닙니다.

| 비교 | 문맥 | 폭 | 층 | 에폭 | 파라미터 | valid PPL ↓ | 학습+검증 초 |
|---|---:|---:|---:|---:|---:|---:|---:|
| baseline | 32 | 64 | 4 | 2 | 300,160 | 147.043 | 7.67 |
| tied | 32 | 64 | 4 | 2 | 251,008 | 198.385 | 7.66 |
| context | 64 | 64 | 4 | 2 | 253,056 | 257.602 | 10.97 |
| width | 64 | 96 | 4 | 2 | 427,840 | 203.103 | 14.31 |
| depth | 64 | 96 | 6 | 2 | 601,344 | 200.568 | 19.49 |
| tokens | 64 | 96 | 6 | 4 | 601,344 | 180.871 | 40.35 |

`baseline`만 가중치를 공유하지 않습니다. `tokens`는 새 문서를 추가한 것이 아니라 같은 train의 노출 횟수를 늘린 것입니다. 모든 후보는 test를 보거나 후보 선택에 사용하지 않았습니다. 작은 학습 예산에서는 확장이 반드시 품질 개선으로 이어지지 않습니다.

## 기본 확대 모델

64토큰·폭96·6층·FFN384·8에폭·CPU 4스레드입니다. 위 비교의 FFN256·최대4에폭과 구분합니다.

- 파라미터 **749,568개**, 학습 정답 **389,440토큰**.
- 최선 epoch **8**, valid PPL **129.508956**, NLL/byte **2.034514**.
- 학습·에폭별 검증 **85.78초**, 정답 **4540.1개/초**, 프로세스 최대 RSS **2253.3 MiB**.
- 색 기억하기 2지선다 4문제의 정답률 **50%**. 정답 단어 전체의 조건부 확률로 비교했습니다. 우연 기준은 50%이며, 짧은 문맥 안/밖 진단만으로 장거리 이해를 입증하지 않습니다.

비교 보고서의 RSS는 한 프로세스의 누적 최대치이므로 각 모델의 단독 최대 메모리로 비교하지 않습니다. 시간도 단일 실행 참고값입니다. 실제 측정은 CPU만 수행했고, CUDA/MPS·AMP·gradient accumulation 성능은 주장하지 않습니다.

## 검증·실행

6개 테스트 통과: 공유 파라미터/gradient·절약량, 64토큰 문맥과 범위 초과, 패킹 격리, 저장 복원, 중간 재개 일치, 변경된 설정/데이터 거부. 앞부분 토큰이 64번째 예측에 영향을 주는 것도 검증했습니다.

```bash
python llm/v0.4/v0.4.3/2.test/test_invariants.py
python llm/v0.4/v0.4.3/1.train/compare.py
python llm/v0.4/v0.4.3/1.train/train.py --device cpu
python llm/v0.4/v0.4.3/2.test/test.py --split valid
python llm/v0.4/v0.4.3/2.test/context_probe.py
```
