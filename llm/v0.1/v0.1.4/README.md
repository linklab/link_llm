# link_llm — 나만의 작은 언어 모델 (v0.1.4)

**2토큰 문맥 신경망.** 지금까지 신경망은 앞 **1토큰**만 봤는데, 비교 상대 v0.0.9(카운트)는
앞 **2토큰**을 봤어요. 그래서 문맥이 짧아 졌던 거예요. v0.1.4 는 신경망도 앞 2토큰을 보게 해
**같은 조건의 공정한 대결**로 만듭니다.

## v0.1.3 → v0.1.4, 무엇이 바뀌었나요?

> **문맥 길이 1토큰 → 2토큰.** 모델 구조·학습·정규화는 그대로, 입력만 넓혔어요.

| | v0.1.0~v0.1.3 | v0.1.4 |
|---|---|---|
| 문맥 | 앞 1토큰 `W[prev]` | 앞 2토큰 `(prev2, prev1)` |
| 입력 | one-hot (V) | one-hot 2개 이어붙임 (2V) |
| 모델 | `nn.Linear(V, V)` | `nn.Linear(2V, V)` |
| 저장 | `W` (V×V) | `W2` (V×2V) |
| 상대 v0.0.9 와 | 문맥이 짧아 불리 | **같은 2토큰 = 공정** |

## 왜 이제 이길 수 있나

1. **같은 문맥(2토큰)** — 더 이상 문맥 길이로 손해 보지 않아요.
2. **부드러움(softmax)** — 카운트는 처음 보는 조합에 `FLOOR=1e-4`라는
   큰 벌점을 주는데(검증 PPL↑), 신경망은 모든 토큰에 부드럽게 확률을 나눠 그 '절벽'을 피해요.
   (`LABEL_SMOOTHING` 은 기본 0 이에요 — `perplexity()` 의 `FLOOR` 가 이미 같은 역할을 해서
   켜면 오히려 검증 PPL 이 나빠집니다. 실측: 0.2 → 검증 PPL +8 정도.)

## 문장 맨 앞의 빈자리 — `<PAD>`

두 번째 토큰을 맞힐 땐 '앞앞 토큰'이 없어요. 그 자리는 **`<PAD>`**(어휘 0번)로 채웁니다.
학습도 추론도 똑같이 "앞앞이 없으면 PAD"로 처리해 일관돼요.

## 실행 방법

> ⚠️ **PyTorch** 필요.
> ```bash
> pip install torch
> ```

```bash
python3 1.train/train.py     # 2토큰 문맥 학습 → 0.model/model.json (W2)
python3 2.test/test.py       # 학습/검증 PPL + 문장 완성 예시
```

검증 PPL 이 **v0.0.9 의 2.96 아래**로 내려가면, "같은 문맥에서 신경망이 카운트를 이겼다".
기본 하이퍼파라미터로 학습하면 **검증 PPL 3.02** 가 나와요 — 카운트(2.96)를 **아슬아슬하게 못 넘습니다**(카운트가 근소하게 더 낮음) ❌
(쉬운 산문이라 격차가 작아요. 진짜 격차는 대화 SFT 인 **v0.5** 에서 벌어집니다.)
(에폭 수는 조기 종료가 정해요 — 이제 **학습 손실**을 기준으로 patience=20 조기 종료해요. 그래서 검증 최적점을 지나 살짝 과적합됩니다.)
(여러 버전 대결표는 다음 버전 **v0.1.5 캡스톤**에서 한 번에 출력합니다.)
