# link_llm — 나만의 작은 언어 모델 (v0.2.3)

**일반화 · 튜닝.** 모델 구조·문맥은 v0.2.2 그대로이고, **학습을 다듬는 도구 3개**를 더합니다.

## 한 걸음 — 도구 3개

| # | 도구 | 코드 | 무엇을 하나 |
|---|---|---|---|
| ① | **dropout** | `nn.Dropout(p)` (tanh 뒤) | 학습 중 은닉 뉴런 일부를 꺼 특정 경로 의존을 막음 |
| ② | **weight tying** | `fc2.weight = emb.weight` | 출력층과 임베딩이 **한 텐서를 공유** → 파라미터 V×H 절약 |
| ③ | **LR 스케줄** | `torch.optim.lr_scheduler` | 학습이 진행될수록 학습률을 줄여 곱게 수렴 |

## 구조

```
(앞 N토큰) → 임베딩 concat(N·E) → fc1 → [BatchNorm(선택)] → tanh → [Dropout] → fc2 → logits(V)
                                                                                ↑ (선택) emb.weight 공유
```

- `DROPOUT=0.0` 이면 Dropout 이 항등이라 **v0.2.2 와 완전히 같아져요**.
- **weight tying 은 `HIDDEN == EMBED` 가 필수**입니다 (`fc2.weight`(V,H) 와 `emb.weight`(V,E) 모양이 같아야 함).
  어긋나면 `lm.py` 가 이유를 설명하며 멈춰요.

| `LR_SCHEDULE` | 동작 |
|---|---|
| `"none"` | 고정 |
| `"cosine"` | 코사인 곡선으로 `LR → LR_MIN` **(기본값)** |
| `"step"` | `LR_STEP` 에폭마다 `LR_GAMMA` 배 |
| `"plateau"` | **검증 PPL 이 정체할 때만** 감소 (조기 종료와 같은 신호) |

| | 학습 PPL | 검증 PPL | 격차 | 파라미터 |
|---|---|---|---|---|
| v0.2.1 (N=3) | 3.00 | 3.37 | 1.12배 | 209,641 |
| v0.2.2 (+초기화·정규화) | 3.25 | 3.48 | 1.07배 | 209,641 |
| **v0.2.3 (+튜닝 3종)** | 2.86 | **3.26** | 1.14배 | **207,305** |

- **v0.2.x 에서 처음으로 개선이 나온 버전**이에요 (3.48 → 3.26).
- 임베딩을 32 → **128** 로 4배 키웠는데 파라미터는 v0.2.2 와 거의 같아요 —
  weight tying 이 `V×H`(1,225×128 ≈ **15.7만 개**)를 돌려줬거든요. **같은 예산으로 4배 넓은 표현.**

## 어느 도구가 기여했나 — `1.train/sweep.py`

v0.2.2 → v0.2.3 은 도구 3개와 `EMBED` 가 **함께** 바뀐 비교라, 그것만으로는 원인을 말할 수 없어요.
그래서 `E=H=128 · N=3` 을 고정한 채 **한 번에 하나만** 켜 봤습니다.

```bash
python3 1.train/sweep.py            # 5개 전부 (MPS 로 약 30분)
python3 1.train/sweep.py --runs all none
```

| 실험 | dropout | tying | schedule | 학습PPL | 검증PPL | 파라미터 | 기준선 대비 |
|---|---|---|---|---|---|---|---|
| none | — | — | — | 3.3394 | 3.5380 | 364,105 | (기준) |
| dropout | 0.1 | — | — | 3.3417 | 3.5406 | 364,105 | +0.003 |
| tying | — | ✅ | — | 3.3861 | 3.6089 | **207,305** | +0.071 |
| cosine | — | — | ✅ | 2.9712 | 3.2920 | 364,105 | **−0.246** |
| **all** | 0.1 | ✅ | ✅ | 2.8575 | **3.2537** | **207,305** | **−0.284** |

**읽는 법**

- **개선분은 거의 전부 LR 스케줄.** −0.284 중 **−0.246** 이 `cosine` 하나의 몫이에요.
- **dropout 은 무효과**(+0.003, 잡음 수준). v0.1.3 의 정규화와 같은 결론 —
  조기 종료가 이미 과적합을 막고 있으면 더 얹을 게 없어요.
- **weight tying 은 단독으로는 손해**(+0.071)지만 **파라미터를 43% 줄여요.**
  전형적인 **크기 ↔ 성능 교환**입니다.
- **그런데 함께 쓰면 이득**: `cosine`(3.2920) → `all`(3.2537) 로 **−0.038 더 좋아지면서
  파라미터는 43% 적어요.** tying 이 준 여유를 스케줄이 살려낸 셈이에요.
- **용량만 키우는 건 답이 아님**: 도구 없이 `E=H=128` 로 키운 `none` 은 파라미터가
  v0.2.2 보다 74% 많은데 검증 PPL 은 오히려 나빠요(3.54 vs 3.48).

> 💡 **교훈: 도구는 따로 재고, 합쳐서도 재야 해요.** 단독으로 손해인 tying 이 조합에선 값을 합니다.
