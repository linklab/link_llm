# link_llm — 나만의 작은 언어 모델 (v0.0.7)

신경망 없이 **단어를 세어** 문장을 만드는 언어 모델이에요. (Python 3 만 있으면 실행)

## v0.0.6 → v0.0.7, 무엇이 바뀌었나요?

> **top-k / top-p 샘플링** — 뽑기 전에 '확률 낮은 꼬리 후보'를 잘라내요.

- 문제: 온도(v0.0.5)만으로는 확률이 아주 낮은 **엉뚱한 꼬리 후보**가 가끔 뽑혀요.
- 해결: 뽑기 **전에** 후보를 걸러냅니다.

- **top-k**: 확률이 높은 **상위 k개** 후보만 남김 (예: `top_k=3` → 상위 3개만)
- **top-p (nucleus)**: 확률을 높은 순으로 더해 **누적 p** 가 될 때까지의 후보만 남김
  (예: `top_p=0.6` → 누적확률 60%까지)
- 남은 후보만 다시 정규화해서 확률에 비례해 뽑아요.

## 데이터: 효과가 보이도록 '머리 크고 꼬리 긴' 분포

문맥 `"나는 오늘"` 뒤에 갈 곳을 일부러 쏠리게 넣었어요:

| 후보 | 학교에 | 공원에 | 도서관에 | 병원에·시장에·바다에·산에·… (꼬리) |
|------|:---:|:---:|:---:|:---:|
| 등장 횟수 | 5 | 3 | 2 | 각 1 (12곳) |

그래서 자르기 설정에 따라 결과가 확 달라져요:

- **무제한**: 꼬리의 드문 장소(동물원에, 박물관에 …)도 종종 나옴 → 다양(때때로 엉뚱)
- **top_k=3**: `학교에 · 공원에 · 도서관에` 만 나옴 → 안정적
- **top_p=0.6**: 머리쪽 몇 곳만 → 꼬리 잘림

```bash
python3 1.train/train.py
python3 2.test/test.py     # 무제한 vs top_k=3 vs top_p=0.6 비교
```

웹앱에도 **top-k · top-p 슬라이더**가 추가됐어요. (v0.0.7 선택 시 효과가 나타나요.)

## 왜 이게 신경망까지 이어지나

- top-k/top-p 는 **확률 분포에만 작용**하는 기법이에요.
- 그래서 분포가 '개수 세기' → '신경망 softmax' 로 바뀌어도 **그대로 재사용**됩니다.
- 오히려 신경망은 어휘 전체에 확률을 흩뿌려 꼬리가 길어서 **더 중요**해져요.
