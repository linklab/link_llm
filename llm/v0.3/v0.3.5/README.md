# v0.3.5 — 공정 비교 캡스톤

## 한 줄 요약

> 카운트·임베딩 MLP·미니 GPT를 같은 데이터로 다시 학습하고, 같은 문맥 비교와 사전 선언한 후보 내 최선 성능 비교를 분리합니다.

## 왜 필요한가?

- 2토큰 카운트와 32토큰 GPT의 점수 차이는 구조뿐 아니라 문맥·용량·학습량의 영향을 받습니다.
- 전체 검증 평균에는 이미 본 문맥이 많이 섞입니다. 학습에서 본 조합 / 문맥은 봤으나 새 정답 조합 / 문맥부터 처음인 자리로 나누어 확인합니다.
- PPL이 좋아도 생성이 비거나 반복될 수 있으므로 같은 프롬프트·온도로 생성 예시와 다양성을 기록합니다.

## 무엇이 바뀌었나?

- **동일 문맥 비교:** 기본 문맥 3토큰으로 세 모델 모두 재학습합니다. 긴 문맥 모델을 평가 때만 잘라서 공정하다고 주장하지 않습니다.
- **후보 내 최선 성능:** 카운트 2/3토큰, MLP 2/3토큰, GPT 3/32토큰의 총 6개 후보를 사전 선언하고 각 계열·시드에서 최저 검증 PPL을 선택합니다. 무제한 튜닝으로 얻은 절대 최대 성능은 아닙니다.
- `--context`를 바꾸면 공통 비교 문맥과 신규성 판정 문맥을 함께 변경합니다. 기본값 2와 겹치는 후보는 중복 학습하지 않습니다.
- 기존 저장본의 학습 이력을 추측하지 않고 같은 원문으로 처음부터 재학습합니다. 입력 파일·체크포인트 SHA-256을 저장합니다.
- 신경망은 공통 시퀀스 창·Adam·학습률 0.003·배치 256·최대 30에폭·patience 5·시드 1234를 사용합니다. 실제 실행 에폭·정답 토큰 노출 수·시간을 기록합니다.
- `--seeds 1234 2345 3456`으로 반복 실행하고 시드별 결과와 PPL 평균·표준편차를 기록할 수 있습니다. 기본 1시드에서는 표준편차를 0으로 꾸미지 않고 null로 둡니다.

## 모델 내부 구조

- **카운트:** v0.0.9의 빈도 표. 1~C토큰 문맥을 저장하고 가장 긴 가용 문맥의 정규화된 분포를 사용합니다.
- **MLP:** v0.2.1의 `Embedding → C개 벡터 연결 → Linear → tanh → Linear` 구조를 그대로 사용합니다. 짧은 문맥은 왼쪽 PAD로 채웁니다. 공통 학습 루프에 연결하기 위해 각 시퀀스 위치에서 해당 문맥의 logits를 내는 어댑터를 추가했습니다. 임베딩 64·은닉 256이며, v0.2.1 과거 저장본/튜닝 설정을 재현하는 실험은 아닙니다.
- **미니 GPT:** v0.3.4의 독립적인 4개 Pre-LN 블록, 4헤드, FFN 256, 최종 LayerNorm, GPT-2식 scaled 초기화를 재사용합니다. 새 attention 구조를 추가하는 버전이 아닙니다.
- 웹앱용 `Model`은 v0.3.4를 상속하되 체크포인트 버전을 v0.3.5로 기록합니다. 첫 번째 지정 시드의 후보 내 최선 GPT를 `0.model/model.pt`에 내보냅니다. 여러 시드 중 가장 좋은 시드를 골라 내보내지 않습니다.

### 공통 채점 계약

- 같은 `punct+josa` 토크나이저, 같은 END, 문장 첫 토큰 제외·END 포함. 토큰 수뿐 아니라 실제 토큰열이 일치하는지 확인합니다.
- 실제 생성 분포에서 정답 확률을 얻고 PPL 계산에만 FLOOR=1e-4를 적용합니다. FLOOR를 적용한 값들을 다시 분포로 정규화하지 않습니다.
- 기존 v0.0.9의 `token_prob()`는 정답이 없으면 더 짧은 문맥으로 이동하지만, 생성의 `next_dist()`는 가장 긴 가용 표를 사용합니다. v0.3.5의 카운트 어댑터는 **정답에 따라 백오프하지 않는 `next_dist()`**로 PPL·순위·생성을 통일합니다. 따라서 기존 카운트 PPL 표와 수치가 달라질 수 있습니다.
- 현재 문맥에 OOV가 있으면 모든 계열이 FLOOR로 채점하고 순위 점수를 주지 않습니다. OOV 정답도 동일합니다. 현재 문맥 밖의 OOV는 영향을 주지 않습니다.
- `support`는 실제 생성 후보 분포에 정답이 포함된 비율입니다. 카운트에서는 문맥이 알려져 있어도 정답 후보가 없을 수 있습니다. 신경망에서는 어휘·문맥의 유효성에 대응합니다.
- 동점은 공통 학습 어휘 순서로 고정합니다. 빈 신규성 집단은 PPL=null / 표에서 N/A로 표시합니다.
- 신규성 판정은 학습 데이터만으로 만들며, 모든 후보에 같은 라벨을 적용합니다. 예: 학습에 `a b → c`가 있으면 `a b → d`는 ‘새 조합’, 학습에 `d a` 문맥이 없으면 ‘새 문맥’입니다.

## 효과

기본 1시드 실측, 동일 3토큰 문맥:

| 모델 | 검증 PPL | top-1 | 규모 |
|---|---:|---:|---:|
| 카운트 | 2.9085 | 76.21% | 20,386 빈도 셀 |
| 임베딩 MLP | 2.6289 | 76.67% | 339,913 파라미터 |
| 미니 GPT | 2.5190 | 77.11% | 315,977 파라미터 |

- 후보 내 최선은 카운트 2토큰(PPL 2.7916), MLP 3토큰, GPT 3토큰입니다. 웹앱용 v0.3.5는 이번 실행에서 **3토큰 GPT**이며 기존 v0.3.4의 기본 문맥 32와 다릅니다.
- GPT 32토큰 PPL은 3.0494입니다. 3토큰보다 긴 문맥에서 OOV가 포함될 자리도 늘어 support가 98.28%→95.53%로 낮아집니다. 긴 문맥 자체가 항상 해롭다고 해석하지 않습니다.
- 동일 문맥의 새 조합 PPL은 카운트 10000, MLP 109.57, GPT 63.52이지만 새 문맥에서는 MLP 218.46, GPT 220.47입니다. 전체 PPL의 우위가 모든 집단의 우위는 아닙니다.
- 각 후보의 시간은 학습·가중치 저장까지이며 후속 평가·생성 시간은 제외합니다. 전체 후보 탐색 비용도 보고서에 별도로 합산합니다.

- 9개 자동 테스트(통합 실행 포함): MLP/GPT 공통 배치 채점과 token_prob 일치, MLP 인과성·왼쪽 PAD, 비기본 설정 저장/복원, 카운트 분포 정규화, 신규성 집단·빈 집단, 토큰열 불일치 거부, 시드별 후보 선택, 재현 가능한 생성.
- 작은 데이터로 6개 후보의 학습→저장→보고서→재로드 평가 및 생성 재현 전체 경로를 검증합니다.
- 실측 표: [comparison_report.md](0.model/comparison_report.md). 상세 설정·에폭별 손실·각 집단 표본 수·생성 예시·시간·데이터/모델 해시: [comparison_report.json](0.model/comparison_report.json).
- 고정 프롬프트 ‘오늘은’, ‘나는’, ‘학교에서’, 최대 새 토큰 40개, 온도 0/0.7, top-k/top-p 제한 없음. 생성 부분만으로 distinct-1/2와 빈 생성 비율을 계산합니다. 의미적 품질 점수로 해석하지 않습니다.

## 한계

- 동일 문맥이어도 동일 파라미터·동일 연산량 실험은 아닙니다. MLP와 GPT의 초기화·비선형 함수·dropout 등도 다릅니다. 구조 하나의 인과 효과를 분리했다는 주장을 하지 않습니다.
- 카운트의 크기는 빈도 셀 수이며 신경망 학습 파라미터 수와 단위가 다릅니다. 토큰 노출 수는 데이터 정답 위치 × 실제 학습 에폭이며, 카운트에서는 데이터 1회 통과 기준입니다. FLOPs 또는 각 차수별 표 업데이트 횟수가 아닙니다.
- 조기종료와 후보 선택에 사용한 검증 세트에 결과를 보고합니다. 독립 최종 테스트가 아니며 선택 편향이 있습니다. 기본 1시드는 통계적 우위를 뒷받침하지 않습니다.
- 기본 후보는 문맥 길이만 탐색합니다. 대규모 모델·학습률·학습 토큰 예산 최적화가 아니므로 결과를 계열의 절대 최고 성능으로 부르지 않습니다.
- 3토큰 기준 ‘새 문맥’은 GPT의 32토큰 전체 문맥이 새로운지와 다른 개념입니다. 공통 기준에서의 일반화 지표입니다.
- 합성 산문 데이터이며 지시 이행·대화 품질 벤치마크가 아닙니다. BPE·KV 캐시·학습 재개 등은 다음 단계입니다.

## 실행

저장소 루트에서 PyTorch가 설치된 Python을 사용합니다.

```bash
# 전체 후보 재학습과 비교, 웹앱용 모델 내보내기
python llm/v0.3/v0.3.5/1.train/train.py
# 반복 시드 실험 (학습 시간 증가)
python llm/v0.3/v0.3.5/1.train/train.py --seeds 1234 2345 3456
# 단위 테스트
python llm/v0.3/v0.3.5/2.test/test_invariants.py
# 데이터/가중치 해시 확인, 저장된 후보들의 전체·집단별 지표와 생성 재현
python llm/v0.3/v0.3.5/2.test/test.py
# 내보낸 GPT로 생성
python llm/v0.3/v0.3.5/2.test/generate.py --prompt "오늘은"
python web_service/server.py
```

- 학습은 CPU로 고정하여 비교 장치 차이를 줄입니다. `--threads`, `--epochs`, `--patience`, `--batch-size`, `--embed`, `--hidden`, `--layers`, `--heads`, `--lr`를 지원합니다.
- 별도 실험은 `--output-dir /tmp/my-experiment`로 분리합니다. 기본 출력 경로로 다시 실행하면 같은 후보의 가중치와 보고서를 갱신합니다.
- 별도 데이터는 `--train`, `--valid`로 지정하고, 재현 검사에도 같은 경로를 전달합니다. 학습 파일과 검증 파일이 동일하거나 내용 해시가 같으면 거부합니다. 부분 중복까지 검출하는 도구는 아닙니다.
- 후보 가중치는 `0.model/candidates/<후보>/0.model/` 아래에 저장합니다. 가중치·어휘 파일은 Git 제외이며 다른 컴퓨터에서 재현하려면 재학습하거나 별도 복사해야 합니다.
