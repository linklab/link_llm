# v0.3.0 — 단일 헤드 셀프어텐션

> 앞 토큰을 이어붙이는 MLP 대신, 현재 토큰의 질문(Q)과 과거 토큰의 열쇠(K)를 비교해 정보(V)를 섞어 다음 토큰을 예측합니다.

## 왜 필요한가?

- v0.2의 MLP는 고정 길이 임베딩을 이어붙여 처리합니다. 이 버전은 각 위치에서 자신과 과거 토큰을 가중합하여 문맥에 따른 표현을 만듭니다.
- 예를 들어 `오늘 / 학교 / ##에서`를 입력하면 세 위치 모두 다음 토큰을 예측합니다. 마지막 위치만 학습하던 인터페이스에서 시퀀스 전체 학습으로 전환합니다.

## 무엇이 바뀌었나?

- 단일 헤드 Q/K/V, `1/sqrt(d_k)` 스케일링, 미래를 볼 수 없는 인과 마스크를 구현했습니다.
- 입력 `(B,T)` → logits `(B,T,V)`로 바뀝니다. 정답은 입력에서 한 토큰 뒤로 이동합니다.
- 문장별 END는 유지하고, 다른 문장을 하나로 이어붙이지 않습니다. 오른쪽 PAD와 이미 채점한 overlap의 정답은 `-100`으로 손실에서 제외합니다.
- 현재 창보다 긴 문장은 첫 창의 모든 정답을 채점한 뒤 한 토큰씩 창을 옮겨 마지막 정답만 채점합니다. 첫 토큰을 제외한 모든 정답과 END가 정확히 한 번 학습됩니다. 각 위치의 문맥은 생성 시 사용하는 최근 `BLOCK_SIZE` 토큰과 같습니다.
- 카운트 계보의 `punct+josa` 토크나이저·END·대화 형식은 재사용합니다. MLP의 학습/평가 코드는 상속하지 않습니다.

## 모델 내부 구조

```text
토큰 ID (B,T)
  → Embedding (B,T,E)
  → Q, K, V 각각 Linear(E,E), bias 없음
  → softmax(QKᵀ / sqrt(E) + causal/PAD mask)
  → 가중합 @ V (B,T,E)
  → Linear(E,V) (B,T,V)
  → 다음 토큰 cross entropy
```

PAD는 입력 배치용이며 출력 후보에서 제외합니다. 전부 PAD인 행에서도 attention과 gradient가 NaN이 되지 않도록 처리합니다.

기본값: 문맥 32토큰, 임베딩 64차원, Adam, 학습률 0.003, 배치 64, 최대 60에폭, 시드 1234. 검증 PPL이 10에폭 동안 개선되지 않으면 중단하고 검증 최저 가중치를 복원합니다. CPU·MPS·CUDA를 지원하며 자동 선택은 CUDA → MPS → CPU 순서입니다.

## 실행

저장소 루트에서 PyTorch가 설치된 Python으로 실행합니다. 현재 컴퓨터에서는 `/opt/anaconda3/envs/link_llm/bin/python`을 사용할 수 있습니다.

```bash
python llm/v0.3/v0.3.0/2.test/test_invariants.py
python llm/v0.3/v0.3.0/1.train/train.py --device cpu
python llm/v0.3/v0.3.0/2.test/test.py --prompt "오늘은"
python web_service/server.py
```

학습 후 웹앱 버전 목록에 `v0.3.0`이 자동 표시됩니다. 다른 설정을 실험하려면 `--embed`, `--block-size`, `--epochs`, `--lr`, `--seed`, `--output-dir`를 지정합니다. 기본 경로로 재학습하면 이 버전의 저장 모델을 갱신합니다.

## 파일과 인터페이스

| 파일 | 책임 |
|---|---|
| `0.model/network.py` | 순수 신경망과 시퀀스 손실 |
| `0.model/sequences.py` | 문장별 슬라이딩 창과 배치 padding |
| `0.model/training.py` | optimizer·학습 루프·검증 최저 선택 |
| `0.model/lm.py` | 어휘·평가·생성·저장/로드·기존 API 연결 |
| `1.train/train.py` | 설정 CLI와 학습 결과/데이터 해시 기록 |
| `2.test/test.py` | 저장 모델 평가와 이어쓰기 |
| `2.test/test_invariants.py` | 미래 누출·PAD·정답 이동·확률 일치·과적합 검증 |

`NGramLM`/`Model` 별칭과 `load`, `generate`, `chat`, `token_prob`, `perplexity`, `accuracy`를 제공합니다. 신경망 자체의 `net(x)`는 이제 `(B,T,V)`이므로 MLP 전용 비교 코드에서 `(B,V)`로 직접 취급하면 안 됩니다. 루트 `eval_suite.py`와 웹 서비스는 공개 API를 사용하므로 그대로 연결됩니다.

`model.pt`는 CPU state_dict와 구조/어휘/평가 설정을 함께 담습니다. `vocab.json`은 사람이 읽는 동일 메타데이터입니다. `training_report.json`에는 설정, 데이터 SHA-256, 실행 환경, 에폭별 손실, 최저 에폭, 학습/검증 지표와 시간이 들어갑니다. 모델 파일만 옮겨도 로드할 수 있습니다. optimizer/RNG를 포함한 정확한 학습 재개는 v0.4에서 구현할 범위입니다.

## 효과와 검증

2026-09-06 기본 설정 CPU 실행 결과: 학습 3,600문장·검증 400문장,
어휘 905개·파라미터 **129,033개**, 검증 최저 **epoch 46**, 56에폭에서 조기종료.
검증 **PPL 3.2405**, **top-1 74.34%**, top-5 81.95%, 유효 문맥/정답 coverage 95.53%,
채점 10,197자리입니다. 학습과 최종 평가에 약 70초가 걸렸습니다(이 컴퓨터 CPU 4스레드).
기존 v0.2.1의 PPL 약 2.37보다 높으며, 성능 개선을 보장하는 버전이 아닙니다.
문맥이 길어져 OOV가 문맥에 포함되는 자리도 늘어나므로 coverage를 함께 봐야 합니다.

생성 예시(입력 `오늘은`, greedy):

> 오늘은 캠핑장에서 하루를 보냈다. 출출해서 치킨을 조금 나눠 먹었다. 틈틈이 노래를 즐겼다. 멀리서 곰이 뛰어노는 모습이 보였다. 괜히 콧노래가 나왔다.

- 미래 토큰을 바꿔도 이전 위치의 logits가 변하지 않습니다.
- PAD를 뒤에 추가해도 실제 토큰의 logits는 같습니다. 제외한 정답 위치에는 gradient가 없습니다.
- Q/K/V와 임베딩으로 유한한 gradient가 전달되며 작은 데이터에 과적합할 수 있습니다.
- 배치 평가와 위치별 `token_prob`로 계산한 PPL이 일치합니다. OOV 정답 또는 OOV가 포함된 현재 문맥은 기존 방식처럼 FLOOR=1e-4로 채점합니다. OOV를 학습된 UNK로 가정하지 않습니다.
- 저장/로드 후 구조 설정과 logits가 일치합니다. 구체적인 실측 결과는 `0.model/training_report.json`을 확인합니다.
- 구조/학습 검증 11개와 웹앱 GET/POST 처리 경로의 버전 검색·생성 호환성을 확인했습니다. 기존 v0.0.9·v0.2.5도 같은 처리 경로로 정상 응답했습니다. 네트워크 배포나 브라우저 UI 전체 검증을 의미하지는 않습니다.

## 한계

- 위치 임베딩(v0.3.2), 멀티헤드(v0.3.1), residual/LayerNorm/FFN(v0.3.3)이 없는 중간 단계입니다. 완성된 Transformer/GPT가 아니며 단어 순서 이해와 긴 문맥 활용이 보장되지 않습니다.
- 기존 2~3토큰 모델과 문맥 길이·파라미터·학습량이 다릅니다. PPL 차이를 어텐션만의 효과로 해석하지 않습니다.
- 현재 합성 산문 데이터와 검증 세트를 사용하며 별도 최종 테스트 세트는 없습니다. 검증 수치는 튜닝에 사용한 결과입니다.
- PPL은 첫 토큰을 제외하고 END를 포함하는 기존 채점 규칙과 FLOOR를 유지한 지표입니다. 확률 하한 없는 순수 언어모델 NLL과 구분합니다.
- 긴 문장의 매 토큰 슬라이딩은 정확성을 우선한 교육용 구현으로 비효율적입니다. 대규모 문서 패킹과 KV 캐시는 아직 없습니다.
- 빈 입력이나 현재 문맥에 OOV가 있으면 생성하지 않습니다. 산문 학습이므로 대화 역할 토큰을 이해하는 SFT 어시스턴트는 아직 아닙니다.
