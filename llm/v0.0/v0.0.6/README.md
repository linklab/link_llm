# link_llm — 나만의 작은 언어 모델 (v0.0.6)

신경망 없이 **토큰을 세어** 문장을 만드는 언어 모델이에요. (Python 3 만 있으면 실행)

## v0.0.5 → v0.0.6, 무엇이 바뀌었나요?

> **토크나이저 — 텍스트를 '어떤 단위로 자를지' 정하는 버전이에요.**
> (백오프 + 확률/온도(v0.0.5)는 그대로 유지해요.)

v0.0.5 까지는 **띄어쓰기**로만 잘랐어요. 여기서 두 가지를 다듬습니다.

### ① 문장부호 분리

```
"좋아!"        →  ["좋아", "!"]
"먹고, 잤어."  →  ["먹고", ",", "잤어", "."]
```

안 나누면 `"좋아"` 와 `"좋아!"` 가 **서로 다른 토큰**이 돼요. 나누면 `"좋아"` 는 항상 같은 토큰이 되고,
**문장부호가 언제 나오는지도** 배울 수 있습니다.

### ② 조사 분리 ← 한국어라서 꼭 필요해요

```
"학교를"  →  ["학교", "##를"]
"오늘은"  →  ["오늘", "##은"]
"오후에는" → ["오후", "##에", "##는"]
```

한국어는 **교착어**라 명사 뒤에 조사가 달라붙어요. 안 나누면 이렇게 됩니다:

```
[바다]  바다로(42) · 바다에(41) · 바다를(34) · 바다에서(27) · 바다는(1)
```

모델에게 이건 **아무 관계 없는 다섯 단어**예요. 실제로 조사를 안 나눈 상태에서
v0.2.5 의 임베딩을 열어보면, `영화관에` 의 최근접이웃은 `동물원에`·`미술관에`(**같은 조사**)였고
정작 형제인 `영화관을` 은 유사도 **−0.01** 로 남남이었어요.
**조사가 어간보다 강한 신호**가 돼버린 겁니다.

### `##` 표시

조사 토큰에는 `##` 를 붙여 **앞 토큰에 붙는 조각**임을 표시해요 (BERT/WordPiece 와 같은 방식).
덕분에 문장으로 되돌릴 때 `학교` + `##를` 를 공백 없이 `학교를` 로 정확히 복원합니다.
실측: 학습·검증 **4,000문장 전부 왕복 복원 성공(실패 0건)**.

## 효과 — 어휘가 26% 줄었어요

| | v0.0.5 (whitespace) | v0.0.6 (punct+josa) |
|---|---|---|
| 어휘 크기 | 1,223 | **903** (−26%) |
| 총 토큰 수 | 72,743 | **92,434** (+27%) |
| 조사 토큰 | — | 19종 (`##이` `##를` `##을` `##가` `##에` …) |

어휘가 줄어든 만큼 **같은 말을 여러 칸에 나눠 외우던 낭비**가 사라지고,
토큰 수가 늘어난 만큼 **문장당 예측할 자리**가 많아집니다.

> ⚠️ **그래서 v0.0.5 이전의 PPL 과는 숫자를 나란히 놓을 수 없어요.**
> PPL 은 '토큰당' 평균이라 자르는 단위가 바뀌면 뜻이 달라집니다. v0.0.6 부터 모든 버전이
> 같은 토크나이저를 쓰므로, **v0.0.6 이후끼리는** 얼마든지 비교할 수 있어요.

## 규칙 기반의 한계 — 숨기지 않아요

사전 없이 **접미 규칙**으로만 자르기 때문에 예외가 남습니다.

| 문제 | 예 | 처리 |
|---|---|---|
| 동사 관형형 | `뛰어노는` → 뛰어노 + ##는 ❌ (어간은 `뛰어놀-`) | `NO_SPLIT` 목록으로 제외 |
| 부사 | `느지막이` 의 `이` 는 주격조사가 아님 | 〃 |
| 조사처럼 끝나는 명사 | `거북이가` → 거북 + ##이 + ##가 ❌ | 〃 |
| 어간이 너무 짧음 | `곁으로` → 곁(1글자)만 남음 | 자르지 않고 통째로 둠 |

**"규칙 + 예외 목록"이 필요하다는 것 자체가 규칙 기반의 한계**예요.
이게 **v0.4.0 에서 데이터로 직접 배우는 BPE** 로 넘어가는 이유입니다.

## 저장되는 모델 형식 (v0.0.6)

`tokenizer` 와 백오프용 `tables` 를 함께 저장해요.

```json
{
  "max_order": 2,
  "tokenizer": "punct+josa",
  "tables": {
    "2": { "학교 ##를": { "갔다": 3 }, "좋습니다 !": { "<END>": 1 } },
    "1": { "학교": { "##를": 12, "##에": 9 }, "!": { "<END>": 8 } }
  }
}
```

`tokenizer` 를 함께 저장하는 이유: **자르는 규칙이 다르면 모델을 비교할 수 없기 때문**이에요.
루트 `eval_suite.py` 가 이 값을 확인해 규칙이 다른 버전은 대결표에서 빼줍니다.

## 사용 방법

```bash
python3 1.train/train.py     # 1) 학습 (문장부호·조사 분리 + 백오프용 표1, 표2)
python3 2.test/test.py       # 2) 문장을 만들어 보기
```

웹앱(`web_service`)은 각 버전의 `tokenizer` 정보를 읽어 자동으로 맞는 방식으로 처리해요.
