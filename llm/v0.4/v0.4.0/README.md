# v0.4.0 — 바이트 BPE·평가 계약

[Notion v0.4 문서](https://app.notion.com/p/3e7860a93eae814e9c9af8976cf54a1e) · [학습 보고서](0.model/training_report.json)

## 한 줄 요약

> 학습 데이터에서 자주 붙어 나오는 UTF-8 바이트 쌍을 합쳐 토큰을 만들고, 첫 토큰부터 원문 전체를 평가합니다.

## 왜 필요한가?

- 기존 `punct+josa`는 규칙 기반으로 단어·조사를 나누며 처음 보는 단어가 OOV가 될 수 있습니다.
- 바이트 BPE는 256개 바이트를 기본 어휘로 가지므로 학습에 없던 단어·한글·이모지도 표현합니다. 표현할 수 있다는 뜻이지 뜻을 이해하거나 자연스럽게 생성한다는 뜻은 아닙니다.
- 토큰 단위를 바꾸면 토큰 수와 PPL의 기준도 달라집니다. 같은 원문과 평가 경계를 고정하고 바이트당 음의 로그우도(NLL)를 함께 기록해야 합니다.

## 무엇이 바뀌었나?

- 표준 라이브러리만 사용하는 결정적 Byte Pair Encoding 구현을 추가했습니다. 임의의 BPE 라이브러리나 GPT 토크나이저와 동일한 분할을 주장하지 않습니다.
- 학습 split만으로 병합 규칙을 만듭니다. 검증 split은 토크나이저 학습이나 어휘 선택에 사용하지 않습니다. 빈도 동률은 토큰 ID 순서로 결정합니다.
- 공백 묶음과 비공백 묶음을 먼저 나눈 뒤 각 묶음 안에서 바이트를 병합합니다. 공백·줄바꿈·대소문자·Unicode를 정규화하거나 삭제하지 않습니다.
- 목표 어휘 768 = 특수 토큰 6 + 바이트 256 + 최대 506개 병합입니다. 병합할 쌍이 소진되면 실제 어휘는 목표보다 작을 수 있습니다.
- PAD=0, EOS=1, BOS=2, USER=3, ASSISTANT=4, SYSTEM=5를 고정 예약합니다. 일반 문자열의 `<EOS>`나 `<USER>`는 그냥 글자로 인코딩합니다. 특수 ID는 `special_id()`로 명시적으로 사용합니다.
- 입력은 `BOS + BPE(원문)`, 정답은 한 칸 뒤의 토큰과 마지막 EOS입니다. 원문의 첫 토큰까지 학습·평가합니다. 빈 문서는 BOS→EOS로 처리합니다.
- 산문 생성 후보는 바이트/BPE 토큰과 EOS입니다. PAD·BOS·역할 토큰은 출력에서 차단합니다. 역할 토큰은 예약만 했고 SFT는 v0.5 범위입니다.
- `model.pt`에 병합 규칙과 모델 설정을 함께 저장합니다. 사람이 확인할 수 있는 `tokenizer.json`, `config.json`, `vocab.json`도 저장합니다. 로드는 체크포인트 내부 설정을 사용하므로 model.pt만 옮겨도 작동합니다.

## 모델 내부 구조

```text
원문 → UTF-8 바이트 → 학습된 BPE 병합 → 토큰 ID
 → BOS / EOS 문서 경계
 → 토큰 + 위치 임베딩
 → 4개 Pre-LN Transformer 블록 (4헤드, FFN 256)
 → 최종 LayerNorm → 출력층
 → PAD/BOS/역할 후보 차단 → 다음 토큰 확률
```

- 네트워크는 v0.3.4의 미니 GPT를 재사용합니다. v0.3.5에서 선택된 3토큰 모델을 그대로 가져오는 것이 아닙니다.
- 기본 문맥 32 BPE 토큰, 임베딩 64, 4층, 4헤드, FFN 256, dropout 0.1입니다. 문맥 32는 이전 토크나이저의 32토큰과 같은 원문 길이가 아닙니다.
- Adam 0.003, 배치 128, 최대 30에폭, 검증 PPL 기준 patience 5, 시드 1234입니다. optimizer/RNG를 포함한 학습 재개는 이후 v0.4.2 범위입니다.
- 각 정답은 정확히 한 번 학습하며 문서 간 정보를 섞지 않습니다. 문맥을 넘으면 최근 32토큰을 보고 위치 번호를 0부터 다시 부여합니다. 문서 패킹과 KV 캐시는 아직 없습니다.

### 기본 설정 CPU 실측

| 항목 | 결과 |
|---|---:|
| 실제 BPE 어휘 | 768개 (특수 토큰 포함) |
| 모델 파라미터 | 300,160개 |
| 검증 토큰 PPL (BPE 전용) | 1.747033 |
| 원문 바이트당 NLL (자연로그) | 0.167113 |
| bits-per-byte | 0.241093 |
| 검증 top-1 / top-5 | 84.98% / 91.29% |
| 검증 문서 / 원문 바이트 | 400개 / 65,840바이트 |
| 검증 정답 토큰 (EOS 포함) | 19,728개 |
| 채택 / 종료 epoch | 21 / 26 |

- 학습 원문 173,728 BPE 토큰 + EOS 3,600개 = 에폭당 정답 177,328자리입니다. 문맥 32에서 슬라이딩 창은 68,250개입니다. 반복 문맥 계산의 비용이 크며 패킹·처리량 개선은 후속 단계에서 다룹니다.
- 학습·검증 문서 4,000개 모두 원문 round-trip을 확인했습니다. 저장본 검증 PPL·원문/EOS NLL·바이트 지표가 보고서와 일치했습니다.
- 새 버전 자동 테스트 12개 및 기존 v0.3.4 테스트 16개가 통과했습니다. 기존 카운트 모델 평가도 정상 동작합니다.
- 웹앱의 v0.4.0 검색·모델 로드·이어쓰기를 확인했습니다. 브라우저 UI 전체나 원격 접속을 검증했다는 의미는 아닙니다.
- 생성 예시(입력 ‘오늘은’, greedy, 최대 새 토큰 40): ‘오늘은 놀이공원에서 하루를 보냈다. 점심으로 치킨을 맛있게 먹었다. 멀리서 돌고래가 뛰어노는 모습이 보였다. 틈틈이 춤을 ’. 토큰 수 제한으로 문장이 중간에 끝날 수 있습니다.

### 지표를 읽는 기준

- 유효한 Unicode 원문은 `decode(encode(text)) == text`로 복원됩니다. 예: `  망고 🥭\t`의 앞 공백과 끝 탭까지 보존합니다.
- 바이트 기본 어휘가 있으므로 OOV 벌점은 없어집니다. 다만 드문 바이트의 실제 확률이 매우 낮아질 수 있습니다.
- **토큰 PPL:** BOS를 조건으로 원문 첫 토큰부터 EOS까지 채점합니다. `log_softmax`로 NLL을 계산하며 기존 FLOOR=1e-4를 적용하지 않습니다.
- **바이트당 NLL:** EOS를 제외한 원문 토큰 NLL 합 ÷ 원문 UTF-8 바이트 수입니다. 자연로그 단위이며 낮을수록 좋습니다. `bits_per_byte = nll_per_byte / ln(2)`도 기록합니다. EOS 비용은 `eos_nll`로 따로 보고합니다.
- 빈 문서도 EOS는 채점하지만 바이트 수는 0입니다. 전체 평가 원문의 바이트 수가 0이면 바이트당 지표는 null입니다.
- 파일의 LF(`\n`)는 문서 구분자이며 채점 원문에 포함하지 않습니다. 그 외 앞뒤 공백·CR·빈 문서는 보존합니다. 파일 SHA-256과 문서별 길이+원문 바이트로 만든 해시를 저장해 평가 원문을 고정합니다.
- 토큰 PPL은 이전 버전과 직접 순위를 매기지 않습니다. `eval_suite.py`의 기존 혼합 순위표는 이 평가 계약을 가진 모델을 제외하고 전용 평가 명령을 안내합니다.
- 바이트당 NLL도 원문·BOS/EOS·확률 하한·문맥 조건을 맞춘 실험끼리 비교해야 합니다. 과거 버전의 FLOOR PPL을 단순히 바이트 수로 나눈 값과 동등하지 않습니다. 결정적 BPE 분할의 토큰 경로 NLL이지 가능한 모든 분할의 확률을 합한 값은 아닙니다.
- 검증 기록과 수치는 `0.model/training_report.json`에 저장됩니다. 독립 최종 테스트 결과는 아닙니다.

## 한계

- BPE는 통계적 압축 규칙이며 의미를 직접 학습하는 기법은 아닙니다. 바이트 하나가 한글 글자의 일부일 수 있습니다.
- 생성 토큰은 임의의 바이트열이 될 수 있습니다. 원문 복원은 strict UTF-8로 검증하지만, 생성 결과 표시에서는 잘못된 UTF-8 또는 길이 제한으로 잘린 문자를 `�`로 표시할 수 있습니다. UTF-8 제약 디코딩은 구현하지 않았습니다.
- 역할 토큰을 예약했다고 대화 모델이 되는 것은 아닙니다. `chat()`은 미지원 오류를 내고 웹앱은 기존처럼 `generate()` 이어쓰기를 사용합니다.
- 모델 API의 빈 입력도 BOS에서 생성합니다. 공용 웹 UI/API도 v0.4.1 구현 시 수정되어 BPE 모델의 빈 입력을 지원합니다. 모델이 학습되지 않은 상태에서는 먼저 학습/로드하라는 오류를 냅니다.
- 현재 데이터는 합성 산문입니다. 코퍼스 출처·중복 제거·패킹·새 분할은 v0.4.1, 학습 안정화·정확한 재개는 v0.4.2에서 다룹니다.
- 단일 시드 검증 결과이며 별도 테스트나 반복 실험 없이 이전 구조보다 좋다고 일반화하지 않습니다.

2. **웹 원문·빈 입력 처리 — 수정:** [웹 UI](../../../web_service/index.html)는 입력을 그대로 전달하고, [서버](../../../web_service/server.py)는 BPE 모델의 원문 보존·빈 입력 생성을 지원합니다. 구형 모델은 기존 trim·빈 입력 거부 규칙을 유지합니다.

## 실행

저장소 루트에서 PyTorch가 설치된 Python으로 실행합니다.

```bash
python llm/v0.4/v0.4.0/2.test/test_invariants.py
python llm/v0.4/v0.4.0/1.train/train.py --device cpu --vocab-size 768
python llm/v0.4/v0.4.0/2.test/test.py --prompt "오늘은"
python web_service/server.py
```

- `--train`, `--valid`, `--output-dir`로 별도 실험을 지정합니다. 같은 경로 또는 파싱한 원문 문서에 교집합이 있으면 거부합니다. 마지막 LF만 다른 파일도 차단합니다. 의미적 유사 중복은 탐지하지 않습니다.
- 학습 모델이 있는 컴퓨터에서는 웹앱이 v0.4.0을 자동 검색합니다. 가중치·어휘 파일은 기존 Git 제외 규칙을 따릅니다.
- 전용 평가 명령은 기본적으로 보고서와 검증 원문 해시가 다르면 거부합니다. 의도적으로 새 데이터를 평가할 때는 `--allow-new-data`를 지정합니다.
- 테스트는 round-trip, 결정적 병합, train-only 학습, 특수 토큰, 모든 정답 1회 채점, 확률 하한 없는 정확한 NLL·바이트 분모, 인과 마스크·gradient, 저장 복원, 손상된 토크나이저 거부, 빈 입력 생성·EOS, 원문 보존, 구형 PPL 순위표 제외, 학습 CLI 전체 경로를 검사합니다.
