# v0.5.0 — 지시·응답 데이터 준비

**대화 예제와 데이터 검증·분할·사람 검수 기록 경로를 구현했습니다. 모델을 학습하는 단계는 아닙니다.**

산문 이어쓰기는 “아침에…” 뒤를 예측합니다. 지시학습은 “다음 글을 한 문장으로 요약해 줘”라는 요청에 맞는 답변을 정답으로 사용합니다. v0.5.0은 그 정답 데이터를 준비합니다. 대화 토큰 직렬화는 v0.5.1, 응답 손실 마스킹은 v0.5.2, 실제 모델 학습은 v0.5.3에서 다룹니다.

## 이번에 준비한 것

| 항목 | 결과 |
|---|---|
| 새 대화 후보 | 48개, 24개 템플릿 그룹 |
| 과제 | 형식 준수·정보 추출·계산·요약·문장 수정·멀티턴·불확실성·안전한 응답 |
| 멀티턴 | 6개 대화; 전체 assistant 응답 54개 |
| 분할 | train 16 / valid 16 / test 16; 각 분할에 8개 과제가 모두 포함 |
| 기본 검사 | 출처·역할 순서·빈 답변·UTF-8·파일/내용 해시·분할 누수·검수 기록 |
| 검증 결과 | 자동 테스트 18개 통과, CLI 준비·감사 실행 성공 |
| 사람 검수 | **미완료: 후보 48개, 승인 0개. `training_ready=false`** |

새 예제는 Codex가 작성한 소규모 교육용 후보입니다. 출처에 AI 작성을 명시했으며, 사람이 작성하거나 검수했다고 표시하지 않았습니다. 현재 품질이 낮은 로컬 base 모델로 답변을 생성하지 않았습니다. 이 48개만으로 실제 대화 품질을 확보했다는 주장은 하지 않습니다.

## 예시

| 과제 | 사용자 요청 | 정답 후보 |
|---|---|---|
| 계산·형식 | 연필 3자루에 4자루를 더 받았어. 숫자만 답해 줘. | `7` |
| 정보 추출 | “민수는 우산을 들고 도서관에 갔다.”에서 사람 이름만 써 줘. | `민수` |
| 멀티턴 정정 | 가방이 파랑이라고 했다가 초록으로 정정 | 최신 정보인 `초록` |
| 모르는 정보 | 내 어제 점심 메뉴를 맞혀 줘. | 정보가 없어 알 수 없다고 답변 |
| 안전한 도움 | 내 계정 비밀번호를 잊었어. | 공식 계정 복구 메뉴 안내 |

정보가 부족하면 확인 질문을 하고, 무해한 요청은 불필요하게 거절하지 않는 예제도 포함합니다. 본문의 `<사용자>`, `<봇>`는 일반 문자열로 보존합니다. 역할은 JSON의 `role` 필드로 구분하므로, 문자열 때문에 대화 경계가 바뀌지 않습니다.

## 데이터와 분할 방식

파일은 저장소의 `data/sft/v0.5.0/`에 있습니다.

- `examples.jsonl`: 원문 대화, 과제, 템플릿, 출처, 답변의 근거. 공백·줄바꿈·한글·이모지를 그대로 저장합니다.
- `sources.json`: 출처·저작 조건·사용 범위·AI 작성 여부.
- `reviews.jsonl`: 사람이 남기는 내용 해시 기반 검수 기록. 현재 비어 있습니다.
- `draft/`: 재현 가능한 후보 train/valid/test와 manifest. **학습용 승인 데이터가 아닙니다.**
- `audit_report.json`: 신규 후보 통계와 기존 데이터 점검 결과.
- `dataset.py`, `review.py`: 준비·로드 검증과 수동 검수 기록 도구. PyTorch 없이 실행됩니다.

같은 템플릿 또는 같은 사용자 발화가 있는 대화는 연결해 한 그룹으로 묶습니다. 멀티턴의 **모든 사용자 발화**를 비교합니다. 중복 제거·검수 제외 전에 그룹을 만들므로, 중간 연결 예제가 빠져도 분할 경계가 바뀌지 않습니다. 비교 키에만 NFC·공백 정규화를 적용하며 원문은 수정하지 않습니다.

과제 조합별 그룹을 시드1234로 섞습니다. 목표 비율은 60/20/20이지만 과제마다 각 분할에 최소 한 그룹을 둡니다. 현재는 과제당 3그룹이라 실제 비율이 **1/3씩**입니다. 독립 그룹이 부족하면 누수를 허용하는 대체 분할 없이 오류를 냅니다. 사람 검수 결과가 바뀌어도 같은 입력 후보·시드의 그룹 배정은 유지합니다. 후보를 추가·수정해 새 데이터셋을 만들 때는 분할을 새 버전으로 고정해야 합니다.

이것은 선언한 템플릿과 정규화 문자열 기준의 분리입니다. 의미가 비슷한 표현까지 탐지하지 않으며, 공개된 예시를 독립적인 일반 언어 능력 벤치마크로 보지 않습니다. 검증·test 예제는 학습에 넣지 않습니다.

## 실행

저장소 루트에서 실행합니다. 기존 사전학습 가중치와 SFT 텍스트는 변경하지 않습니다.

```bash
# 후보 데이터 재생성: 모델 학습이 아님
python llm/v0.5/v0.5.0/1.train/prepare.py
# 후보·기존 데이터 점검
python llm/v0.5/v0.5.0/2.test/test.py
# 자동 테스트
python llm/v0.5/v0.5.0/2.test/test_invariants.py
```

검증에는 원문 보존, 정규화 중복의 연결 관계, 멀티턴 후속 지시 누수, 해시를 다시 쓴 데이터의 누수, 조작된 manifest, 오래된 검수 기록, 출처/역할 오류, 입력 덮어쓰기 방지, CLI 실행을 포함합니다. 전체 학습이나 base 대비 생성 품질 비교는 수행하지 않습니다.

## 사람이 검수한 데이터로 전환하기

검수자는 원문과 정답을 읽고 **지시 준수·정확성·자연스러움·문맥 일관성·안전성**을 확인합니다. 모든 assistant 턴을 확인해야 합니다. 틀린 내용은 먼저 `examples.jsonl`에서 수정합니다.

아래 명령은 실제 사람이 검수를 완료했을 때만 사용합니다. 자동 검사나 AI 판단을 사람 검수로 기록하지 않습니다.

```bash
python data/sft/v0.5.0/review.py --id sft050-001 \
  --decision approved --reviewer '실제 검수자 이름' \
  --note '두 항목 형식과 내용의 적절성을 직접 확인함' \
  --checked instruction_following correctness naturalness context_consistency safety

# 부적절한 후보는 제외: --checked 생략 가능
python data/sft/v0.5.0/review.py --id sft050-002 \
  --decision rejected --reviewer '실제 검수자 이름' --note '제외 이유'

# 각 분할·과제에 승인 예제를 확보한 뒤 실행
python llm/v0.5/v0.5.0/1.train/prepare.py --mode reviewed \
  --output-dir data/sft/v0.5.0/reviewed
python llm/v0.5/v0.5.0/2.test/test.py \
  --dataset data/sft/v0.5.0/reviewed --require-reviewed
```

승인 기록은 예제 전체 내용의 해시와 연결됩니다. 승인 후 응답·출처·과제 등을 바꾸면 다시 검수해야 합니다. 미검수/거절 예제는 승인 데이터에 들어가지 않으며, 분할별 과제 범위가 부족하면 내보내기를 거부합니다. `load_bundle()`은 기본적으로 사람 검수 데이터만 허용합니다. 후보를 읽을 때만 명시적으로 `for_training=False`를 사용합니다.

검수 기록은 로컬 선언이며 검수자의 신원을 인증하는 시스템은 아닙니다. 사람 검수 완료 여부는 이름을 채우는 것만으로 확보되지 않습니다.

## 기존 SFT 데이터 점검

`data/sft/train.txt` 3,600개와 `valid.txt` 400개에서 형식 오류·분할 내 정규화 대화 중복·분할 간 동일 사용자 발화는 각각 0개였습니다. 기존 파일은 그대로 유지했습니다.

하지만 템플릿 분리와 개별 정답 검수 기록은 없습니다. 예를 들어 “멕시코 어디 있어?”에 “멕시코, 멀지만 가볼 만해요!”라고 답하는 예제는 위치 질문에 답하지 않습니다. “저는 자주 먹어요”처럼 모델의 경험을 지어내는 표현도 원본 생성기에 있어 점검이 필요합니다. 자동 감사의 표본 목록은 검수 대상 표시이며, 모든 표본이 오류라는 판정은 아닙니다. 기존 자료를 새 정답 데이터로 자동 승격하지 않았습니다.

## 범위와 남은 일

- 이번 완료 범위는 **데이터 후보·출처·분할·검증·검수 도구**입니다. 사람의 정답 검수와 규모 확장은 남아 있습니다.
- v0.4.7 코드에 발견된 기존 버전의 소스 고정 검사 오류·v0.4.5 보고서 불일치는 별도 문제이며 이 단계에서 수정하지 않았습니다. 새 데이터 준비는 해당 모델 코드에 의존하지 않습니다.
- 새 모델 가중치나 `0.model/lm.py`를 만들지 않았습니다. 웹 모델 목록에도 v0.5.0이 나타나지 않습니다. 데이터만 추가한 버전이기 때문입니다.
- v0.5.1에서는 이 `messages`를 공통 대화 템플릿으로 직렬화합니다. 이후에도 검수 상태·분할 경계를 보존해야 합니다.
