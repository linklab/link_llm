# link_llm — 나만의 작은 언어 모델 (v0.0.9)

신경망 없이 **단어를 세어** 문장을 만드는 언어 모델이에요. (Python 3 만 있으면 실행)
**개수 세기 시대(v0.0.x)의 마지막 버전**입니다.

## v0.0.8 → v0.0.9, 무엇이 바뀌었나요?

> **퍼플렉서티(perplexity) 평가 + 데이터 정비** — "얼마나 잘 맞히나?" 를 숫자로 재요.

### 1) 퍼플렉서티(PPL)

지금까지는 문장을 눈으로 보고 "그럴듯하네" 정도로 판단했어요.
v0.0.9 는 **하나의 숫자**로 모델의 실력을 잽니다.

- 각 토큰의 확률 `p` 를 구해서 → **PPL = exp( 평균( -log p ) )**
- **낮을수록 좋아요.** (1이면 완벽, 클수록 헷갈림)
- 직관: *"다음 토큰을 정할 때 평균 몇 개 중에서 헷갈리나."* PPL=5 면 5개 중 하나 고르는 수준.

### 2) 데이터 정비 (학습 / 검증 분리)

사전학습용 산문 코퍼스 공용 데이터 `data/pretrain/` 을 학습용(train.txt)·검증용(valid.txt) 둘로 나눴어요.

- `pretrain/train.txt` — **학습용** (모델이 외우는 산문)
- `pretrain/valid.txt` — **검증용** (학습에 없는 '처음 보는' 문장)

두 곳의 PPL 을 비교하면 모델이 **외우기만 하는지, 일반화하는지** 알 수 있어요.

### 3) 순위로 재는 평가 — top-1 / top-5 정확도

PPL 은 **"확률을 얼마나 잘 배분했나"** 를 봅니다. 그런데 실제로 쓸 때 중요한 건
**"1등으로 찍은 게 정답이냐"** 인 경우가 많아요. 그래서 `accuracy()` 를 같이 잽니다.

| 지표 | 묻는 것 |
|---|---|
| `top1` | 1등으로 찍은 토큰이 정답인 비율 |
| `topk` | 정답이 상위 k(기본 5)개 안에 든 비율 |
| `coverage` | 정답이 **후보 목록에 있기라도 한** 비율 |

**`coverage` 가 이 시대의 한계를 드러내는 숫자예요.**
- 표에 없는 조합은 확률을 줄 방법 자체가 없어요 → 아무리 잘 골라도 틀립니다.
- PPL 에서는 `FLOOR` 가 메워 가려지는데, `coverage` 는 그대로 보여줍니다.

> 💡 **두 지표는 순위가 뒤바뀔 수 있어요.** 검증 PPL 이 더 낮은 모델이 top-1 정확도는 오히려
> 더 낮은 경우가 실제로 생겨요(뒤 v0.1.x 버전들끼리 비교해 보면 나타납니다).
> "지표를 하나만 보면 안 된다"가 이 저장소에서 실제로 일어납니다.

## 실행 결과

```bash
python3 1.train/train.py     # 학습 (pretrain/train.txt)
python3 2.test/test.py       # 평가 (PPL + 정확도)
```

```
학습 데이터(3600문장) PPL :   2.30   ← 외운 것이라 낮음
검증 데이터(400문장)  PPL :   2.65   ← 처음 보는 것이라 조금 높음
→ 검증이 학습보다 약간 높음 = '외우기 vs 일반화' 격차

--- 순위로 재는 평가 (검증 자리) ---
top-1 정확도       :  73.5%   ← 1등으로 찍은 토큰이 정답
top-5 정확도       :  80.8%
정답이 후보에 있음 :  97.1%   ← 나머지 약 2.9% 는 표에 아예 없어서 못 맞혀요
```

**읽는 법**
- 개수 세기 모델은 **본 것만 잘 맞혀요** — 처음 보는 조합엔 약합니다(백오프·바닥값에 의존).
- 신경망(v0.1.x~)은 softmax 라 어휘 전체에 확률이 퍼져 `coverage` 가 **98.9%** 로 올라가요.
- 97.1% vs 98.9% 의 차이가 곧 **백오프의 한계**입니다.
- 이 PPL(2.65)이 신경망과 비교할 **기준선**이 됩니다. 파라미터는 **8,883개** — 전 버전 중 가장 작아요.
