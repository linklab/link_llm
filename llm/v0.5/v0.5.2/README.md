# v0.5.2 — 응답 토큰만 학습하기

v0.5.1의 **사람 승인 대화 48개**를 실제 손실 계산에 사용할 입력·정답으로 변환합니다. assistant 응답 54개를 각각 한 번씩 채점합니다. 이번 버전은 데이터·배치·손실 계산까지 구현하며, 가중치 이식과 반복 학습은 v0.5.3에서 진행합니다.

## 무엇이 달라지나요?

예를 들어 사용자가 “1 더하기 1은?”이라고 묻고 정답이 “2입니다.”이면, 질문을 그대로 따라 쓰는 능력에 점수를 매기지 않고 **답변을 맞혔는지** 평가합니다.

```text
토큰열: BOS USER [질문] EOT ASSISTANT [답변] EOT EOS
채점:     제외되는 입력 문맥           [답변] EOT EOS
```

| 대상 | 손실에 포함? |
|---|---|
| 시스템 지침·사용자 질문·역할 토큰 | 제외 (`-100`) |
| 이전 assistant 응답 | 현재 예제에서는 제외; 그 응답의 별도 예제에서 채점 |
| 이번 assistant 응답 본문·EOT | 포함 |
| 원본 대화의 마지막 EOS | 마지막 응답 예제에서만 포함 |
| 길이를 맞추기 위한 PAD | 제외 (`-100`) |

질문은 여전히 모델의 입력입니다. 질문 위치의 예측 결과를 직접 채점하지 않는다는 의미이며, 질문의 임베딩이나 어텐션으로 기울기가 전달되지 않는다는 뜻은 아닙니다.

## 멀티턴은 어떻게 처리하나요?

두 번 주고받는 대화는 두 예제로 만듭니다.

1. `질문1 → 답변1`: 답변1과 EOT를 채점합니다.
2. `질문1 → 답변1 → 질문2 → 답변2`: 앞선 대화는 문맥으로만 사용하고 답변2·EOT·EOS를 채점합니다.

답변1이 두 번째 예제에 다시 나타나도 중복 채점하지 않습니다. 중간 응답 뒤에 대화 종료 EOS를 붙이지 않아 아직 끝나지 않은 대화를 종료하도록 가르치지 않습니다. 빈 응답에도 EOT는 채점합니다.

## 긴 대화 처리

기본값은 `--context 256 --overflow reject`입니다. 입력 길이가 넘으면 내보내기 전에 오류를 냅니다. 현재 54개 예제는 전부 들어가며, 자르거나 제외한 예제는 **0개**입니다.

선택 옵션 `--overflow drop-oldest-pairs`는 해당 응답보다 앞선 **가장 오래된 user/assistant 쌍을 통째로** 제거합니다. 시스템 지침, 현재 질문, 이번 응답은 반드시 보존합니다. 그래도 길면 오류를 냅니다. 본문이나 UTF-8 바이트 중간을 자르지 않습니다.

삭제한 원본 메시지 번호를 `dropped_message_indices`에 기록합니다. 앞선 이름·목록을 참조하는 대화는 과거 문맥을 제거하면 정답의 근거가 사라질 수 있습니다. 이 옵션의 결과는 다시 검토해야 하며, `training_ready`는 원본 사람 승인 상태를 뜻합니다. 기본 배포는 이 옵션을 사용하지 않습니다.

## 손실 계산과 배치 계약

`input_ids = 토큰열[:-1]`이며 `labels`는 다음 토큰을 **이미 한 칸 이동한 정답**입니다. `logits[:, t]`와 `labels[:, t]`를 바로 비교하세요. 학습 실행기에서 다시 이동시키면 정답 위치가 어긋납니다.

`collate()`는 오른쪽에 PAD=0, labels=-100을 채우고 `attention_mask`를 반환합니다. 현재 v0.5.1 네트워크는 PAD ID로 attention을 차단하므로 `net(input_ids)`로 호출합니다. 다른 모델에 연결할 때는 해당 모델의 마스크 인터페이스를 따라야 합니다.

`response_loss(logits, labels)`는 **채점 대상 토큰 전체의 평균 cross entropy**와 토큰 수를 반환합니다. 예제별 평균을 다시 평균내지 않습니다. 모델이 역할 토큰 출력에 `-inf`를 사용해도 제외 위치를 먼저 걸러내므로 불필요한 NaN이 발생하지 않습니다.

채점 토큰이 0개인 배치는 미분 가능한 0과 개수 0을 반환합니다. 이때 호출자는 **optimizer·scheduler 단계를 건너뛰어야 합니다.** 그렇지 않으면 weight decay로 가중치가 바뀔 수 있습니다. 데이터 변환 단계에서는 assistant가 없는 대화를 거부합니다.

## 실행

저장소 루트에서 실행합니다. 변환과 파일 검증은 Python 표준 라이브러리, 손실·모델 테스트는 PyTorch를 사용합니다.

```bash
conda activate link_llm
# 승인된 v0.5.1 최종 데이터 → 응답별 입력·정답
python llm/v0.5/v0.5.2/1.train/prepare.py
# 저장 파일을 원본으로부터 재계산해 비교
python llm/v0.5/v0.5.2/1.train/prepare.py --check
# 응답 본문·종료 토큰·추론 입력 일치 검증
python llm/v0.5/v0.5.2/2.test/test.py
# 마스크·기울기·길이·배포 테스트
python llm/v0.5/v0.5.2/2.test/test_invariants.py
```

다른 입력은 `--source`, 다른 출력은 `--output-dir`로 지정합니다. 입력은 v0.5.1의 승인된 prepared 형식이어야 하며, 미검수 데이터는 거부합니다. 같은 결과는 재생성할 수 있지만 다른 내용은 덮어쓰지 않습니다. 원본 승인·분할·템플릿을 `prepared/source/`에 복사하고 해시와 실제 재인코딩 결과를 검사합니다.

|---|---:|---:|---:|---:|---:|
| train | 16 | 18 | 494 | 207 | 0 |
| valid | 16 | 18 | 573 | 221 | 0 |
| test | 16 | 18 | 364 | 183 | 0 |

총 **54개 응답·1,431개 정답 토큰**을 확인했습니다. EOT 54개와 EOS 48개가 포함됩니다. 원본 분할과 익명 사람 승인 기록을 유지했습니다.

- 신규 테스트 12개: 정답 이동·응답별 1회 채점·PAD·특수 문자열·빈 응답·채점 대상 없는 배치·길이 경계·쌍 제거·변조·미검수 거부·실제 모델 기울기·배치/개별 출력 일치.
- v0.5.1 회귀 28개도 통과해 이번 검증은 총 40개입니다. 배포 재생성과 저장 검증 보고서의 일치도 확인했습니다.
- 실제 모델 검증은 무작위 초기화한 v0.5.1 네트워크의 순전파·역전파입니다. optimizer 업데이트나 SFT 성능 평가는 수행하지 않았습니다.
- 손실 함수는 프롬프트 위치 logits의 기울기 0, 응답 위치의 기울기 발생, 전체 파라미터 기울기의 유한성을 확인했습니다.

주요 파일은 `0.model/sft_data.py`(예제·배치·손실), `1.train/prepare.py`(내보내기), `2.test/test.py`(원본 대비 검증), `2.test/verification_report.json`(저장 결과)입니다.

다음 단계인 v0.5.3에서 사전학습 가중치 이식, EOT 어휘 확장, optimizer·재개·평가를 연결해 실제 SFT를 수행합니다.
